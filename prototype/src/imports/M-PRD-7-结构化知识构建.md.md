## 1. 模块定位

### 1.1 一句话定位
将标准化文档候选集中的目标内容，按照"先选知识形态，再选知识类目"的顺序，构建为结构化知识对象（一期支持 FAQ 与术语）。

### 1.2 模块价值
明确落实"目标先行"和"知识形态决定构建方式"的设计原则，将非结构化材料转化为高质量、结构清晰的知识对象，为 Agent 提供准确的知识来源。

### 1.3 本模块负责
- 支持知识运营人员优先选择目标**知识形态**（一期为 FAQ / 术语）。
- 支持在选定知识形态下，联动选择对应的**知识类目**。
- 支持从标准化文档候选集中选择目标内容进入对应构建通道。
- 将目标内容构建为结构化知识对象（FAQ / 术语）。
- 支持知识运营人员与知识运营 Agent 的协同构建。

### 1.4 本需求不做
- 非结构化切片构建（由 M-PRD-8 负责）。
- 二维表、分类树、决策表、SOP、知识图谱等复杂结构化形态（二期及以后扩展）。
- 质检与治理（如查重、冲突检测等，一期不纳入，二期由 M-PRD-9 负责）。
- 项目方案的定义与修改（由 M-PRD-4 负责）。
- 知识包的最终验收与生成（由 M-PRD-10 负责）。

### 1.5 上下游边界
- **上游输入**：
  - 项目方案配置（来自 M-PRD-4，提供知识类目与知识形态的映射关系）。
  - 标准化文档候选集（来自 M-PRD-6 标准化处理）。
- **下游输出**：
  - 结构化知识对象（FAQ、术语）。
- **与其他模块的关系**：
  - [M-PRD-8 非结构化切片构建]：相互独立，结构化通道不依赖知识切片作为前置。同一份标准化文档的不同内容可分别进入两个通道。
  - [M-PRD-10 知识包管理]：本模块产出的启用的结构化知识对象，将作为知识包的组成部分。

## 3. 使用场景

### 3.1 场景一：人工主导的结构化知识构建
- **场景描述**：知识运营人员需要从产品说明书中提取常见问题。他首先在系统中选择知识形态为"FAQ"，系统联动显示项目方案中配置为 FAQ 的知识类目（如"售后规则"）。他选择"售后规则"类目，然后从标准化文档中圈选相关段落，手动提取并录入问答对。
- **触发角色**：知识运营人员
- **前置条件**：项目方案已配置（包含 FAQ 形态及对应类目），且已存在标准化文档候选集。
- **预期结果**：成功生成归属于"售后规则"类目、形态为"FAQ"的结构化知识对象。

### 3.2 场景二：Agent 辅助的结构化知识构建
- **场景描述**：知识运营人员需要提取大量行业术语。他选择知识形态"术语"及对应类目后，选中多份标准化文档，触发知识运营 Agent 进行自动化抽取。Agent 完成后，人工进行结果核对和调整。
- **触发角色**：知识运营人员（触发）、知识运营 Agent（执行）
- **前置条件**：同上。
- **预期结果**：Agent 自动生成一批术语对象，经人工确认后落库。

### 3.3 异常/边界场景：未配置对应形态的类目
- **场景描述**：知识运营人员选择了"术语"形态，但当前项目方案中没有任何知识类目被定义为"术语"形态。
- **触发角色**：知识运营人员
- **前置条件**：项目方案配置中缺失特定形态的映射。
- **预期结果**：系统提示当前项目方案未配置该形态的类目，引导用户前往项目方案（M-PRD-4）进行调整。

## 4. 核心对象

| 对象 | 是否新对象 | 对象说明 | 关键属性（中文） | 关联状态/关系 |
|------|------------|----------|-----------------|---------------|
| 结构化知识对象 | 否 | 经结构化通道形成的知识结果（一期为 FAQ、术语） | 对象ID、内容数据、所属类目、知识形态 | 状态：启用/停用；关系：N:1 知识类目，N:1 知识形态 |
| 知识形态 | 否 | 目标知识的组织形式，是构建的首要决策维度 | 形态名称、形态类型 | 关系：1:1 知识类目（在同一项目方案内） |
| 知识类目 | 否 | 用于承载某一类目标知识内容的配置项 | 类目名称、层级 | 关系：1:1 知识形态（在同一项目方案内） |
| 标准化文档 | 否 | 原始材料经过标准化处理后的统一处理对象 | 文档ID、内容、来源 | 关系：1:N 结构化知识对象 |

### 4.1 对象约束补充
- **结构化知识对象** 的唯一性规则：在同一知识类目下，一期不强制系统级全局去重（质检为二期能力），但需记录唯一标识。
- **结构化知识对象** 的归属关系：每个结构化知识对象必须明确归属一个知识类目，并具有明确的知识形态。
- **结构化知识对象** 的可用条件：状态为"启用"时，方可被 M-PRD-10 纳入知识包。

## 5. 业务事实归属与状态一致性

### 5.1 业务事实归属
- **[某个结构化知识对象归属哪个知识类目与知识形态]** 的唯一事实来源是：结构化知识对象本身的属性记录。
- **[某个结构化知识对象来源于哪份标准化文档]** 的唯一事实来源是：来源追溯关系记录。
- **[某个知识类目对应什么知识形态]** 的唯一事实来源是：项目方案（M-PRD-4 的输出）。

### 5.2 状态一致性要求
- 本文档涉及的结构化知识对象状态必须与《概念模型》一致，仅包含：**启用 / 停用**。
- 不引入"草稿"、"待审核"等复杂状态，结果验收不在此处体现。

## 7. 详细功能需求

### 7.1 功能点一：构建目标选择（先形态，后类目）

#### 功能描述
在启动结构化知识构建前，知识运营人员必须先明确要构建的知识形态，再选择具体的知识类目，从而确定本次构建的目标。

#### 触发角色
- 知识运营人员

#### 前置条件
- 项目知识空间已创建，且当前项目方案已生效。
- 项目方案中至少配置了一个属于结构化通道的知识形态（FAQ 或 术语）。

#### 输入
- 用户的选择操作。

#### 正常流程
1. 系统展示当前阶段支持的结构化知识形态选项（FAQ、术语）。
2. 用户选择某一目标知识形态（如：FAQ）。
3. 系统读取当前项目方案，筛选出配置为该知识形态的所有知识类目。
4. 系统以下拉列表或树状结构展示这些匹配的知识类目。
5. 用户选择具体的目标知识类目。

#### 异常/拦截
- 当 [项目方案中未配置任何结构化知识形态] 时，系统应：拦截操作，提示"当前项目方案未包含结构化知识目标，请先完善项目方案"。
- 当 [用户选定知识形态后，发现项目方案中无对应类目] 时，系统应：置空类目选择器，并提示"当前方案下无对应此形态的知识类目"。

#### 输出结果
- 确定的构建目标组合：[知识形态 + 知识类目]。

#### 状态变化
- 无对象状态变化，仅为前端会话状态。

#### 业务规则
- **形态优先规则**：必须先选择知识形态，知识类目选择器才能激活。
- **联动过滤规则**：知识类目列表必须严格受限于已选的知识形态，仅展示 1:1 映射关系匹配的类目。

#### 与其他模块的边界/影响
- 本功能依赖 M-PRD-4（项目方案配置）提供的映射数据。

---

### 7.2 功能点二：候选内容选择与结构化构建

#### 功能描述
在确定构建目标后，从标准化文档候选集中选择相关内容，并通过人工或 Agent 执行构建，生成结构化知识对象。

#### 触发角色
- 知识运营人员
- 知识运营 Agent

#### 前置条件
- 已完成功能点一（选定知识形态与知识类目）。
- 标准化处理已完成，存在标准化文档候选集。

#### 输入
- 选定的标准化文档或具体段落内容。
- 人工录入的结构化数据（如问题、答案、术语名称、解释）或 Agent 的抽取指令。

#### 正常流程
1. 系统展示标准化文档候选集列表。
2. 用户浏览并勾选相关文档或圈选具体内容片段。
3. 用户选择构建方式（人工构建 或 Agent 自动抽取）。
4. 若为人工构建：系统提供对应知识形态的表单（如 FAQ 的问答对表单），用户填入并保存。
5. 若为 Agent 抽取：系统将选定内容与目标形态指令发送给 Agent，Agent 返回结构化结果，用户进行核对和调整后保存。
6. 系统生成结构化知识对象，并建立与源标准化文档的来源追溯关系。

#### 异常/拦截
- 当 [用户提交的结构化数据缺失必填项（如 FAQ 缺答案，术语缺解释）] 时，系统应：拦截保存，提示"请完善结构化必填信息"。

#### 输出结果
- 新增的结构化知识对象（FAQ 或 术语）。
- 建立的来源追溯关系。

#### 状态变化
- 新生成的结构化知识对象：默认状态为 [启用]。

#### 业务规则
- **独立通道规则**：结构化知识对象直接来源于标准化文档，不依赖知识切片。
- **多形态复用规则**：同一份标准化文档的不同内容，可以分别被选中构建为不同知识形态的结果。

#### 与其他模块的边界/影响
- 本功能不对内容进行跨文档的查重或冲突校验（此为 M-PRD-9 质检与治理的二期职责）。
- 产出的对象将流入 M-PRD-10（知识包管理）。

## 8. 自然语言伪代码

### 8.1 主流程：构建目标选择与执行流程

```text
当 [知识运营人员] 执行 [发起结构化构建] 动作时，系统执行：
1. 校验 [当前项目方案是否已生效]；
2. 若 [未生效]，则返回 [拦截结果：请先完成项目方案配置]；
3. 接收用户选择的 [知识形态]（如 FAQ）；
4. 读取项目方案，过滤出形态为 [该知识形态] 的 [知识类目列表]；
5. 若 [列表为空]，则返回 [提示：该形态下无可用知识类目]；
6. 接收用户选择的 [知识类目]；
7. 接收用户从候选集中选择的 [目标内容]；
8. 接收用户提交的 [结构化数据]（人工或 Agent 产出）；
9. 校验 [结构化数据是否符合形态要求（如非空）]；
10. 若 [不符合]，则返回 [拦截结果：数据格式不完整]；
11. 创建 [结构化知识对象]；
12. 建立该对象与 [目标内容] 的 [来源追溯关系]；
13. 将该对象状态设置为 [启用]；
14. 返回 [成功结果]。
```

## 9. 关键业务规则

| 规则编号 | 规则内容 | 优先级 |
|----------|----------|--------|
| R-STR-01 | **目标先行（形态优先）**：知识构建必须按"先选知识形态，再选知识类目"的顺序进行，明确"要构建什么形式的知识"。 | 高 |
| R-STR-02 | **候选集筛选原则**：标准化处理后的标准化文档集合构成候选输入范围；各知识类目应从该范围中选择相关内容进入对应构建通道。 | 高 |
| R-STR-03 | **通道独立性**：结构化知识对象直接基于标准化文档构建，绝不依赖非结构化知识切片作为前置。 | 高 |
| R-STR-04 | **复用性原则**：同一份标准化文档中的不同内容，可以分别构建为不同知识形态的结果，互不冲突。 | 中 |

## 10. 异常与边界情况

| 场景 | 触发条件 | 处理方式 | 用户提示 |
|------|----------|----------|----------|
| 形态无类目 | 选定知识形态后，项目方案中无对应类目 | 置空类目选项，阻止进入下一步 | "当前项目方案未配置该形态的知识类目，请前往项目方案调整" |
| 候选集为空 | 进入内容选择时，未进行过标准化处理 | 列表显示为空 | "暂无标准化文档候选集，请先完成原始材料的标准化处理" |
| 必填项缺失 | 保存结构化对象时，缺失问题/答案/术语名 | 拦截保存动作 | "请填写完整的[字段名]信息" |

### 10.1 特殊边界补充
- **构建目标变更边界**：若在 M-PRD-4 中修改了某类目的知识形态，本模块中已生成的历史结构化知识对象不自动改写或删除，是否重建由知识运营人员明确确认。

## 13. 依赖与约束

### 13.1 业务依赖
- 强依赖 **M-PRD-4 项目方案配置** 提供的知识类目与知识形态的 1:1 映射关系。
- 强依赖 **M-PRD-6 标准化处理** 提供的标准化文档候选集。

### 13.2 业务约束
- 本期（一期）仅支持 FAQ 和术语两种结构化知识形态，不得将二维表、SOP 等复杂形态作为主流程必填项。
- 质检（去重、冲突检测）不作为本期构建时的强制拦截条件。

### 13.3 外部影响说明
- 本模块产出的启用的结构化知识对象，将直接决定 M-PRD-10（知识包管理）中可用于打包的结构化内容质量。
