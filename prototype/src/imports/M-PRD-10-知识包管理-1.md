## 1. 模块定位

### 1.1 一句话定位

将项目内已启用的结构化知识对象和/或知识切片组织为带有版本信息的知识包，管理知识包的启用/停用，使其成为 Agent 可实际消费的场景知识交付单元。

### 1.2 模块价值

- **对知识运营团队**：提供知识结果的统一汇聚入口，支持知识运营人员将分散在不同知识类目、不同知识形态下已完成构建的知识结果，有序组织成一个可交付的整体，并管理其生效状态。为知识交付提供明确的边界与版本控制，确保业务在不同时期使用的知识集合可追溯、可回滚。通过“同一时间仅一个版本启用”的机制，保障知识检索结果的一致性与稳定性。
- **对 Agent 使用链路**：知识包是 Agent 实际检索与调用的知识交付对象，而不是直接面向分散的结构化知识对象或知识切片。知识包的组织与启用是连接"知识构建"与"Agent 使用"之间的桥梁。
- **对企业客户**：知识包是客户查看并进行结果验收的核心对象，客户看到的是完整的知识结果集合，而不是内部处理中间态。
- **对整体闭环**：知识包是知识工程主链路最终阶段的核心输出，是项目知识运营从"构建结果"迈向"可用知识"的关键一步。

### 1.3 本模块负责

- 将已启用的结构化知识对象（一期：问答对、术语条目）和/或已启用的知识切片，组织为知识包
- 创建知识包，指定知识包名称与包含的知识结果范围
- 管理知识包的启用/停用状态
- 维护知识包与其包含的结构化知识对象、知识切片之间的组成关系
- 展示知识包的基本内容概览，包括包含的知识结果类型、数量
- 知识包版本的列表管理与状态维护
- 支持知识运营人员查看知识包详情，了解其具体内容组成
- 向下游 M-PRD-11 构建结果验证提供可验证的知识包对象
- 向下游 C-PRD-2 结果验收提供企业客户可查看的知识包展示

### 1.4 本需求不做

- 不负责结构化知识对象的构建（由 M-PRD-7 负责）
- 不负责知识切片的构建（由 M-PRD-8 负责）
- 不负责构建结果验证与搜索测试（由 M-PRD-11 负责）
- 不负责企业客户结果验收（由 C-PRD-2 负责）
- 不设计 Agent 运行时对话系统（系统外范围）
- 不设计外部 Agent 调用的接口协议细节（一期不展开）
- 不设计完整的质检与治理流程（由 M-PRD-9 负责，二期）
- 不设计项目管理、审批流、交付管理功能
- 不设计知识包版本对比与差异分析（属二期增强范围）
- 不自动同步上游知识结果的状态变更（上游知识结果状态变更后，需知识运营人员手动更新知识包组成）

### 1.5 上下游边界

- **上游输入**：
  - M-PRD-7 结构化知识构建：提供状态为"启用"的结构化知识对象（一期：问答对、术语条目），供知识包选用
  - M-PRD-8 非结构化切片构建：提供状态为"启用"的知识切片，供知识包选用
- **下游输出**：
  - 处于启用状态的特定版本知识包。
  - M-PRD-11 构建结果验证：已启用的知识包是搜索测试与可用性检查的目标对象
  - C-PRD-2 结果验收：已启用的知识包是企业客户查看和验收的主要呈现对象
- **与其他模块的关系**：
  - M-PRD-4 项目方案配置：项目方案定义了知识类目与知识形态，知识包中的组成内容应与项目方案中定义的知识类目对齐，但本模块不负责修改项目方案
  - M-PRD-7 / M-PRD-8：本模块不负责修改上游结构化知识对象或知识切片的状态；上游知识结果变更时，本模块感知但不自动重组知识包

## 3. 使用场景

### 3.1 场景一：首次生成知识包

- **场景描述**：项目内结构化知识对象和/或知识切片已完成构建并启用，知识运营人员将其汇聚，创建并启用项目第一个知识包，供后续验证与交付使用
- **触发角色**：知识运营人员
- **前置条件**：
  - 项目知识空间处于"启用"状态
  - 项目方案处于"启用"状态
  - 项目内至少存在一个"启用"状态的结构化知识对象（问答对或术语条目）或至少一条"启用"状态的知识切片
- **预期结果**：知识包创建成功，包含指定的知识结果，知识包状态设置为"启用"，可被 M-PRD-11 验证，可被 C-PRD-2 展示给企业客户

### 3.2 场景二：更新知识包组成（新增内容）

- **场景描述**：原始材料补充上传并完成标准化与知识构建后，产生新的结构化知识对象或知识切片，知识运营人员将其纳入当前启用的知识包，更新知识包内容
- **触发角色**：知识运营人员
- **前置条件**：当前项目已有处于"启用"状态的知识包；有新增的"启用"状态的结构化知识对象或知识切片待纳入
- **预期结果**：知识包组成内容更新成功，创建新版本（如 V2.0），新增内容已纳入知识包 ，确认无误后启用新版本，旧版本自动停用，实现平滑升级。

### 3.3 场景三：更新知识包组成（移除内容）

- **场景描述**：知识运营人员发现某些知识结果不应继续出现在知识包中（如对应知识对象已停用，或需调整范围），将其从知识包中移除
- **触发角色**：知识运营人员
- **前置条件**：当前项目已有处于"启用"状态的知识包；知识包中存在需要移除的内容
- **预期结果**：指定内容从知识包中移除，创建新版本（如 V2.0），知识包其余内容保持不变，知识包状态不变，确认无误后启用新版本，旧版本自动停用，实现平滑升级。

### 3.4 场景四：停用知识包

- **场景描述**：知识运营人员决定暂停当前启用的知识包（如准备替换为更新版本），将其停用
- **触发角色**：知识运营人员
- **前置条件**：当前项目存在处于"启用"状态的知识包
- **预期结果**：知识包状态变为"停用"，不再对 Agent 和企业客户展示为当前可用的知识结果

### 3.5 场景五：查看知识包内容详情

- **场景描述**：知识运营人员在交付前或日常运营中，进入知识包详情页，查看知识包包含的全部知识结果及组成概览
- **触发角色**：知识运营人员
- **前置条件**：项目内已存在至少一个知识包
- **预期结果**：详情页展示知识包名称、状态、包含的结构化知识对象数量（按知识类目分组）、包含的知识切片数量（按知识类目分组），并可逐条浏览组成内容

### 3.6 异常/边界场景：知识包中包含的知识结果被上游停用

- **场景描述**：知识包已启用，但知识包中包含的某条结构化知识对象或知识切片被知识运营人员在上游模块（M-PRD-7 或 M-PRD-8）中停用
- **触发角色**：知识运营人员（在上游模块操作）
- **前置条件**：知识包处于"启用"状态；被停用的知识结果已被纳入该知识包
- **预期结果**：系统在知识包详情页标注"包含已停用内容"的提示；不自动将该内容从知识包中移除；由知识运营人员确认是否更新知识包组成

### 3.7 异常/边界场景：知识包无任何启用内容时尝试启用

- **场景描述**：知识运营人员尝试启用一个组成内容为空（或组成内容全部处于"停用"状态）的知识包
- **触发角色**：知识运营人员
- **前置条件**：目标知识包中无任何"启用"状态的知识结果
- **预期结果**：系统拦截并提示"该知识包中无可用知识内容，无法启用"

| 对象 | 是否新对象 | 对象说明 | 关键属性（中文） | 关联状态/关系 |
|------|------------|----------|-----------------|---------------|

| 知识切片 | 否 | 来自 M-PRD-8 产出的非结构化切片，是知识包的组成来源之一 | 切片内容摘要、所属知识类目、启用状态 | 被知识包引用；启用状态由 M-PRD-8 管理 |

### 4.1 对象约束补充

- **知识包**的唯一启用约束：同一项目知识空间内，同一时间最多一个知识包处于"启用"状态；若当前已有启用的知识包，启用新知识包时，系统自动将原有启用知识包切换为"停用"状态并提示知识运营人员确认。
- **知识包**的非空约束：知识包必须至少包含一个"启用"状态的知识结果方可被启用。
- **知识包组成关系**的引用约束：知识包可同时引用结构化知识对象和知识切片；知识包不限定只包含某一种类型。
- **知识包组成关系**与上游状态的独立性：知识包组成关系仅记录"哪些知识结果被纳入"，不自动跟随上游知识结果的启停状态变化而变更；若上游知识结果被停用，知识包中的引用关系仍保留，但系统在知识包详情中标注相关提示。
- **结构化知识对象与知识切片**的可选性规则：知识包可只包含结构化知识对象，或只包含知识切片，或同时包含两者；由知识运营人员根据项目方案的知识类目与知识形态灵活决定。
- 知识包组成关系的归属关系：组成关系强依赖于知识包版本，记录的是引用而非物理拷贝；多个版本之间知识形态保持一致（均可包含结构化知识与切片）。
- 知识包版本的可用条件：必须至少包含一条有效（未被删除）的知识结果引用，且必须在项目方案处于“启用”状态时方可操作。

## 5. 业务事实归属与状态一致性

### 5.1 业务事实归属（Source of Truth）

- **当前对 Agent 和企业客户生效的知识结果是什么**的唯一事实来源是：知识包对象的当前启用状态，以及该知识包中包含的知识结果组成。
- **某个知识包是否处于启用状态**的唯一事实来源是：知识包对象自身的启用状态属性。
- **某条结构化知识对象或知识切片是否处于可被选入的启用状态**的唯一事实来源是：各自对象自身的启用状态属性（分别由 M-PRD-7、M-PRD-8 管理）。
- **知识包中包含哪些知识结果**的唯一事实来源是：知识包组成关系。
- **某条知识结果是否已被纳入某个知识包**的唯一事实来源是：知识包组成关系中的引用记录。
- 知识包版本启用/停用状态的唯一事实来源是：本模块中的知识包版本对象状态。

### 5.2 状态一致性要求

- 本文档涉及的对象状态必须与《概念模型 V4.2》一致。
- 知识包的状态有且仅有"启用"和"停用"两种，与《概念模型 V4.2》保持一致。
- 结构化知识对象和知识切片的状态由各自上游模块管理，本模块只读取，不修改。
- 不允许在正文、伪代码、验收标准中出现相互冲突的状态名。
- 知识包的启用状态变更后，知识包列表页、知识包详情页应立即反映最新状态；C-PRD-2 结果验收模块所读取的知识包状态应与本模块保持一致。
- 任何状态切换必须严格遵循“同一项目内仅一版本启用”的互斥原则。

## 7. 详细功能需求

### 7.1 功能点一：创建知识包

#### 功能描述

知识运营人员在项目知识空间内创建一个新的知识包，填写名称并从当前项目中已启用的结构化知识对象和/或知识切片中选择内容，完成知识包的初始组成配置。

#### 触发角色

- 知识运营人员（主动触发）或知识运营 Agent（授权执行）

#### 前置条件

- 项目知识空间处于"启用"状态
- 项目方案处于"启用"状态
- 项目内至少存在一个"启用"状态的结构化知识对象（问答对或术语条目）或至少一条"启用"状态的知识切片

#### 输入

- 知识包名称（必填）
- 选择的知识结果范围：
  - 来自 M-PRD-7 的启用状态的结构化知识对象（问答对、术语条目，按知识类目分组展示）
  - 来自 M-PRD-8 的启用状态的知识切片（按知识类目分组展示）

#### 正常流程

1. 知识运营人员在知识包管理列表页点击"创建知识包"
2. 系统展示创建知识包面板，包含知识包名称输入框，以及按知识类目分组的可选知识结果列表
3. 知识运营人员填写知识包名称
4. 知识运营人员在按知识类目分组的结构化知识对象列表中，勾选本次纳入的问答对和/或术语条目
5. 知识运营人员在按知识类目分组的知识切片列表中，勾选本次纳入的知识切片
6. 知识运营人员确认创建
7. 系统校验知识包名称不为空且至少选择了一条知识结果
8. 系统创建知识包对象，初始状态为"停用"
9. 系统建立知识包与所选知识结果之间的知识包组成关系
10. 返回成功结果，知识包出现在知识包管理列表页

#### 异常/拦截

- 当知识包名称为空时，系统应拦截并提示"知识包名称不可为空"
- 当未选择任何知识结果时，系统应拦截并提示"请至少选择一条知识结果"
- 当同项目内已存在同名知识包时，系统应提示"该项目下已存在同名知识包，是否继续创建"，允许知识运营人员确认后继续（允许重名，但提示确认）
- 当项目内无任何"启用"状态的知识结果时，系统应拦截进入创建面板，提示"当前项目内无可用的知识结果，请先完成结构化知识构建或非结构化切片构建并启用相关结果"

#### 输出结果

- 新建的知识包（状态为"停用"）
- 知识包与所选知识结果之间的知识包组成关系

#### 状态变化

- 知识包对象：由"不存在"变为"停用"

#### 业务规则

- 知识包初始创建后默认状态为"停用"，需知识运营人员手动启用
- 知识包创建时可同时包含结构化知识对象和知识切片，两者均为可选，不强制两者都有
- 知识包中的知识结果选择以"启用状态"为筛选前提，只允许选择上游模块中状态为"启用"的知识结果
- 创建知识包时，系统按知识类目对可选知识结果分组展示，便于知识运营人员按类目选择
- 知识包名称在项目内允许重名，但系统应提示确认

#### 与其他模块的边界/影响

- 本功能不负责：结构化知识对象的创建与状态管理（由 M-PRD-7 负责）
- 本功能不负责：知识切片的创建与状态管理（由 M-PRD-8 负责）
- 本功能对下游的输出是：已创建的知识包（停用状态），知识运营人员启用后供 M-PRD-11 验证与 C-PRD-2 展示

### 7.2 功能点二：启用知识包

#### 功能描述

知识运营人员将某个"停用"状态的知识包切换为"启用"状态，使其成为项目当前对 Agent 和企业客户生效的知识结果。由于同一项目内同一时间仅允许一个知识包处于"启用"状态，启用新知识包前系统需提示处理原有启用知识包。

#### 触发角色

- 知识运营人员

#### 前置条件

- 目标知识包当前状态为"停用"
- 目标知识包中至少包含一个"启用"状态的知识结果

#### 输入

- 目标知识包（已选定）

#### 正常流程

1. 知识运营人员在知识包管理列表页或知识包详情页，点击目标知识包的"启用"操作
2. 系统校验目标知识包中是否存在至少一条"启用"状态的知识结果
3. 系统判断当前项目内是否已存在另一个处于"启用"状态的知识包
4. 若存在，系统提示"当前项目已有启用状态的知识包【XXX】，启用此知识包后，原有知识包将自动停用，是否继续"
5. 知识运营人员确认后，系统将原有启用知识包的状态更新为"停用"
6. 系统将目标知识包从"停用"更新为"启用"
7. 返回成功结果

#### 异常/拦截

- 当目标知识包中无任何"启用"状态的知识结果时，系统应拦截并提示"该知识包中无可用知识内容，无法启用"
- 当目标知识包中包含被上游模块停用的知识结果时，系统应在启用前展示提示"该知识包包含已停用的知识内容，启用后这些内容将不可被检索，是否继续"，允许知识运营人员确认后继续
- 当知识运营人员取消替换确认时，保持现有启用知识包和目标知识包的状态均不变

#### 输出结果

- 目标知识包状态更新为"启用"
- 原有启用知识包（如存在）状态更新为"停用"
- 操作结果反馈

#### 状态变化

- 目标知识包对象：由"停用"变为"启用"
- 原有启用知识包（如存在）：由"启用"变为"停用"

#### 业务规则

- 同一项目知识空间内，同一时间最多一个知识包处于"启用"状态
- 启用知识包时，若当前已有启用知识包，必须经知识运营人员明确确认后方可替换
- 知识包中包含处于"停用"状态的知识结果不阻止启用，但应有前置提示
- 知识包的启用是将其设为当前项目的生效知识结果，是面向 Agent 和企业客户的关键操作

#### 与其他模块的边界/影响

- 本功能对下游的输出是：处于"启用"状态的知识包，可供 M-PRD-11 构建结果验证使用，可供 C-PRD-2 结果验收展示给企业客户

### 7.3 功能点三：停用知识包

#### 功能描述

知识运营人员将当前"启用"状态的知识包切换为"停用"状态，停止其作为当前生效知识结果的作用。

#### 触发角色

- 知识运营人员

#### 前置条件

- 目标知识包当前状态为"启用"

#### 输入

- 目标知识包（已选定）

#### 正常流程

1. 知识运营人员在知识包管理列表页或知识包详情页，点击目标知识包的"停用"操作
2. 系统提示"停用后，该知识包将不再作为当前生效知识结果，是否确认停用"
3. 知识运营人员确认后，系统将目标知识包从"启用"更新为"停用"
4. 返回成功结果

#### 异常/拦截

- 当目标知识包当前状态已为"停用"时，系统提示"该知识包已处于停用状态"

#### 输出结果

- 目标知识包状态更新为"停用"
- 操作结果反馈

#### 状态变化

- 知识包对象：由"启用"变为"停用"

#### 业务规则

- 停用操作不删除知识包本身及其组成关系，可重新启用
- 停用后项目内不存在启用状态的知识包，不强制要求必须有启用的知识包

#### 与其他模块的边界/影响

- 本功能不负责：通知下游 Agent 运行时停止使用该知识包（由外部集成承接，系统外范围）
- 本功能对下游的影响是：M-PRD-11 和 C-PRD-2 读取知识包状态时将感知到无当前启用知识包

---

### 7.4 功能点四：查看知识包列表

知识运营人员查看当前项目知识空间内所有知识包记录，包括知识包名称、状态、包含内容数量摘要、创建时间等信息。

### 7.5 功能点五：查看知识包详情

#### 功能描述

知识运营人员或企业客户查看某个知识包的完整内容组成，包括按知识类目分组的结构化知识对象列表和知识切片列表，以及每条知识结果的基本内容摘要和来源信息。

#### 触发角色

- 目标知识包已存在

#### 输入

- 目标知识包（已选定）

- 当目标知识包不存在时，提示"该知识包不存在或已被删除"

#### 输出结果

- 知识包详情：基本信息 + 按知识类目分组的知识结果列表

#### 状态变化

- 无状态变化（仅读取）

#### 业务规则

- 知识包详情按知识类目分组展示，对齐项目方案中的知识类目结构

- 企业客户通过 C-PRD-2 承接查看，本模块只需保证详情页内容结构完整，不在本模块单独设计企业客户侧的展示交互

### 7.6 功能点六：更新知识包版本

#### 功能描述
为保证版本的不可变性与可追溯性，对已有知识包版本组成的更新操作，将以“另存为新版本”的方式进行，原版本保持不变。

#### 触发角色
- 知识运营人员

#### 前置条件
- 目标版本存在。

#### 输入
- 新版本名称
- 增删后的知识结果集合

#### 正常流程
1. 知识运营人员在某版本详情页点击“更新组成”。
2. 系统带入该版本原有的知识结果勾选状态，并展示项目内其他可选内容。
3. 知识运营人员调整勾选状态，输入新版本名称。
4. 确认提交后，系统基于新的勾选集合创建一个全新的知识包版本，状态为“停用”。

#### 异常/拦截
- 当更新后的集合为空时，系统应拦截并提示“版本至少需保留一条知识结果，无法将组成清空”。

#### 输出结果
- 全新的知识包版本对象及其组成关系。

#### 状态变化
- 原知识包版本：保持不变。
- 新知识包版本：状态为“停用”。

#### 业务规则
- 对知识包组成的任何修改都不应直接覆盖原版本，以保证历史版本随时可查、可回滚。

#### 与其他模块的边界/影响
- 无特殊影响。

## 8. 自然语言伪代码

### 8.1 主流程：创建知识包

```text
当 知识运营人员 执行 创建知识包 时，系统执行：
1. 校验 当前项目知识空间是否处于"启用"状态；
2. 若 不是，则返回 提示"当前项目知识空间已停用，无法创建知识包"；
3. 校验 当前项目方案是否处于"启用"状态；
4. 若 不是，则返回 提示"当前项目方案已停用，无法创建知识包"；
5. 校验 项目内是否存在至少一条"启用"状态的结构化知识对象或知识切片；
6. 若 不存在，则返回 提示"当前项目内无可用的知识结果，请先完成结构化知识构建或非结构化切片构建并启用相关结果"；
7. 展示 创建知识包面板，按知识类目分组展示可选的启用状态结构化知识对象和知识切片；
8. 知识运营人员 填写知识包名称并选择知识结果；
9. 校验 知识包名称是否为空；
10. 若 为空，则返回 提示"知识包名称不可为空"；
11. 校验 是否至少选择了一条知识结果；
12. 若 未选择任何知识结果，则返回 提示"请至少选择一条知识结果"；
13. 创建 知识包对象，状态为"停用"；
14. 建立 知识包与所选知识结果之间的知识包组成关系；
15. 返回 成功结果，知识包出现在列表中。
```

### 8.2 主流程：启用知识包

```text
当 知识运营人员 执行 启用知识包 时，系统执行：
1. 校验 目标知识包是否存在；
2. 若 不存在，则返回 提示"该知识包不存在"；
3. 校验 目标知识包当前状态是否为"停用"；
4. 若 已为"启用"，则返回 提示"该知识包已处于启用状态"；
5. 校验 目标知识包中是否存在至少一条"启用"状态的知识结果（即引用对象中，上游启用状态为"启用"的数量 ≥ 1）；
6. 若 不存在，则返回 提示"该知识包中无可用知识内容，无法启用"；
7. 判断 目标知识包中是否包含被上游停用的知识结果（即引用对象中，上游启用状态为"停用"的数量 ≥ 1）；
8. 若 存在，则提示"该知识包包含已停用的知识内容，启用后这些内容将不可被检索，是否继续"；
   若 知识运营人员取消，则保持知识包状态不变，流程结束；
9. 判断 当前项目内是否已存在另一个处于"启用"状态的知识包；
10. 若 存在，则提示"当前项目已有启用状态的知识包【XXX】，启用此知识包后，原有知识包将自动停用，是否继续"；
    若 知识运营人员取消，则保持知识包状态不变，流程结束；
    若 知识运营人员确认，则将 原有启用知识包 从"启用"更新为"停用"；
11. 将 目标知识包 从"停用"更新为"启用"；
12. 返回 成功结果。
```

### 8.3 主流程：更新知识包组成

```text
当 知识运营人员 执行 更新知识包组成 时，系统执行：
1. 展示 当前知识包已包含的知识结果（含各条上游状态标注）；
2. 展示 项目内其他"启用"状态的可选知识结果；
3. 知识运营人员 勾选/取消勾选 知识结果；
4. 知识运营人员 确认更新；
5. 计算 更新后知识包组成是否为空；
6. 若 为空，则返回 提示"知识包至少需保留一条知识结果，无法将组成清空"；
7. 若 目标知识包当前处于"启用"状态，则进一步校验 更新后知识包中是否有至少一条上游为"启用"状态的知识结果；
8. 若 无，则提示"更新后该知识包将不包含任何可用内容，建议先停用知识包再更新，是否继续"；
   若 知识运营人员取消，则保持知识包组成不变，流程结束；
9. 新增 本次勾选新增的知识结果的知识包组成关系；
10. 删除 本次取消勾选的知识结果的知识包组成关系；
11. 更新 知识包最后更新时间；
12. 返回 成功结果。
```

### 8.4 异常流程：知识包中的知识结果被上游停用

```text
当 知识运营人员 查看处于"启用"状态的知识包详情时，系统执行：
1. 读取 知识包组成关系中的所有引用对象；
2. 对每条引用对象，检查其在上游模块中的当前启用状态；
3. 若 某条引用对象的上游启用状态为"停用"，则：
   在详情页该条目旁标注"来源已停用"提示；
4. 统计 全部引用对象中，上游为"停用"状态的数量；
5. 若 存在，则在知识包详情页顶部展示提示"当前知识包中包含 N 条已停用的知识内容，建议更新知识包组成"；
6. 知识包本身状态不自动变更；
7. 知识运营人员可从此处直接触发"更新知识包组成"操作。
```

### 8.5 状态切换流程：停用知识包

```text
当 知识运营人员 执行 停用知识包 时，系统执行：
1. 校验 目标知识包是否存在；
2. 若 不存在，则返回 提示"该知识包不存在"；
3. 校验 目标知识包当前状态是否为"启用"；
4. 若 已为"停用"，则返回 提示"该知识包已处于停用状态"；
5. 提示 "停用后，该知识包将不再作为当前生效知识结果，是否确认停用"；
6. 若 知识运营人员取消，则保持知识包状态不变；
7. 若 知识运营人员确认，则将 目标知识包 从"启用"更新为"停用"；
8. 返回 成功结果。
```

## 10. 异常与边界情况

| 场景 | 触发条件 | 处理方式 | 用户提示 |
|------|----------|----------|----------|
| 创建时未填写名称 | 知识包名称字段为空 | 拦截操作 | "知识包名称不可为空" |
| 创建时未选择任何知识结果 | 未勾选任何结构化知识对象或知识切片 | 拦截操作 | "请至少选择一条知识结果" |
| 项目内无可用知识结果 | 项目内无"启用"状态的知识结果 | 拦截进入创建面板 | "当前项目内无可用的知识结果，请先完成结构化知识构建或非结构化切片构建并启用相关结果" |
| 启用无有效内容的知识包 | 目标知识包中无任何"启用"状态的引用对象 | 拦截启用操作 | "该知识包中无可用知识内容，无法启用" |
| 启用时存在另一已启用知识包 | 项目内已有另一处于"启用"状态的知识包 | 提示确认替换 | "当前项目已有启用状态的知识包【XXX】，启用此知识包后，原有知识包将自动停用，是否继续" |
| 启用时知识包中含已停用内容 | 知识包中存在上游状态为"停用"的引用对象 | 提示确认，允许继续 | "该知识包包含已停用的知识内容，启用后这些内容将不可被检索，是否继续" |
| 停用已停用的知识包 | 对"停用"状态的知识包执行停用操作 | 提示当前已是目标状态 | "该知识包已处于停用状态" |
| 启用已启用的知识包 | 对"启用"状态的知识包执行启用操作 | 提示当前已是目标状态 | "该知识包已处于启用状态" |
| 更新后知识包组成为空 | 更新知识包时取消勾选所有内容 | 拦截更新操作 | "知识包至少需保留一条知识结果，无法将组成清空" |
| 上游知识结果被停用后，知识包中含已停用内容 | 知识包处于"启用"状态，其引用对象被上游模块停用 | 在详情页标注提示，不自动处理 | "当前知识包中包含 N 条已停用的知识内容，建议更新知识包组成" |
| 项目方案已停用时进入知识包管理 | 项目方案处于"停用"状态 | 拦截创建操作，允许查看已有知识包 | 创建时提示"当前项目方案已停用，无法创建知识包" |
| 并发操作同一知识包 | 两人同时操作同一知识包 | 以后提交者为准，提示冲突 | "该知识包已被其他运营人员修改，请刷新后重试" |

### 10.1 特殊边界补充

- **知识包历史记录保留**：项目内可保留多个知识包记录（含停用的历史版本），不强制删除历史知识包，便于知识运营人员回溯历史内容组成。
- **同一知识结果被多个知识包引用**：同一条结构化知识对象或知识切片，可同时被多个知识包引用（含历史停用知识包），不产生冲突。
- **知识包中的知识结果仅为引用关系**：知识包组成关系记录引用，不复制内容；删除上游知识结果后，知识包中对应引用关系失效，在详情页标注"来源已删除"提示，知识包整体不自动停用。
- **一期不设计知识包版本管理**：一期基础版不提供知识包版本记录、版本对比与回滚能力，属二期增强范围。
- **一期不展开外部 Agent 调用协议**：知识包启用后对外提供检索能力，一期不在本模块展开具体接口协议细节（如 MCP / API 调用规范）。

## 13. 依赖与约束

### 13.1 业务依赖

- 本模块依赖 M-PRD-7 结构化知识构建提供的已启用结构化知识对象（一期：问答对、术语条目），作为知识包的候选组成来源之一
- 本模块依赖 M-PRD-8 非结构化切片构建提供的已启用知识切片，作为知识包的候选组成来源之一
- 本模块依赖 M-PRD-4 项目方案配置提供的知识类目结构，用于知识包内容的分组展示
- 本模块的输出（已启用的知识包）是 M-PRD-11 构建结果验证的验证目标，也是 C-PRD-2 结果验收的展示对象

### 13.2 业务约束

- 一期知识包组成来源仅包含：问答对（M-PRD-7）、术语条目（M-PRD-7）、知识切片（M-PRD-8）；二维表、分类树、决策表、SOP 等其他结构化知识形态为二期范围
- 知识包不替代单一知识结果；知识包是多个知识结果的有序集合
- 同一时间项目内只有一个启用知识包
- 知识包启停操作需知识运营人员明确确认，不自动执行
- 外部 Agent 调用知识包的接口协议细节不在本模块一期展开
- 质检结果不在本模块中处理；质检与治理属二期能力（M-PRD-9）
- 同一时间项目内绝对且仅允许一个版本处于启用状态。
- 版本的更新必须采用“另存为新版本”的快照模式，不可直接篡改已固化版本的组成。


### 13.3 外部影响说明

- 本模块的输出（已启用的知识包）会影响：M-PRD-11 构建结果验证（以知识包为验证对象）；C-PRD-2 结果验收（企业客户查看知识包内容）；外部 Agent 检索能力（通过知识包对外提供知识消费入口）
- 本模块输出的唯一“启用版本”是 M-PRD-11 构建结果验证及 Agent 实际检索消费的唯一事实来源。
- 本模块依赖的共享规则包括：《概念模型 V4.2》中的知识包、知识包组成关系、结构化知识对象、知识切片的对象定义与状态定义；《角色矩阵与权限边界 V3.2》中的知识运营人员权限定义；《分期规划与能力边界 V1.1》中一期范围约束
