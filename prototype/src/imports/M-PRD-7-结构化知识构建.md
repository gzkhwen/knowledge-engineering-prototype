## 1. 模块定位

### 1.1 一句话定位

从标准化文档候选集中，按照"先选知识形态，再选知识类目"的顺序，将其构建为结构化知识对象（一期仅限问答库与术语两种知识形态），供知识包生成使用。

### 1.2 模块价值

- **对知识运营团队**：提供结构化知识构建的操作入口，支持人工触发或 Agent 执行，将原始文档中散落的问答信息和术语定义转化为可检索、可管理、可追溯的结构化知识对象。
- **对 Agent 使用链路**：问答库与术语是 Agent 处理高频查询与准确理解业务概念的核心知识形态，一期交付的结构化结果将直接纳入知识包并对 Agent 开放。
- **对知识工程闭环**：本模块是整条知识工程主链路中结构化通道的核心执行环节，与非结构化切片通道并行，共同支撑知识包的完整性。


### 1.3 本模块负责
- 接收标准化文档候选集
- 支持知识运营人员优先选择目标**知识形态**（一期为 问答库 / 术语）。
- 支持在选定知识形态下，联动选择对应的**知识类目**。
- 支持从标准化文档候选集中选择目标内容进入对应构建通道。
- 将目标内容构建为结构化知识对象（问答库 / 术语）。
- 针对知识形态为"问答库"的知识类目，构建问答对（问题 + 标准答案 + 来源）形式的结构化知识对象
- 针对知识形态为"术语"的知识类目，构建术语条目（术语名称 + 释义 + 别名 + 来源）形式的结构化知识对象
- 支持 AI 辅助抽取与人工编辑（创建、修改、删除、启用/停用）
- 维护结构化知识对象与来源标准化文档之间的来源追溯关系


### 1.4 本需求不做

- 一期不做以下结构化知识形态：二维表、分类树、规则库/决策表、流程库/SOP、知识图谱（均为二期及以后）
- 不负责标准化文档的生成与管理（由 M-PRD-6 负责）
- 不负责项目方案的定义与变更（由 M-PRD-4 负责）
- 不负责非结构化切片的构建（由 M-PRD-8 负责）
- 不负责质检与治理（由 M-PRD-9 负责，二期）
- 不负责知识包的组织与启用（由 M-PRD-10 负责）
- 不负责构建结果验证（由 M-PRD-11 负责）
- 不负责企业客户结果验收（由 C-PRD-2 负责）
- 不设计复杂工具配置回写（工具配置为二期能力）
- 不设计完整审批流


### 1.5 上下游边界

- **上游输入**：
  - M-PRD-4 项目方案配置：提供当前项目方案（知识类目 + 知识形态），是本模块启动的前置依据
  - M-PRD-6 标准化处理：提供可供本模块选择的标准化文档候选集
- **下游输出**：已启用的问答库结构化知识对象和/或术语结构化知识对象，供 M-PRD-10 知识包管理选用
- **与其他模块的关系**：
  - M-PRD-8 非结构化切片构建：与本模块并行，处理不同知识形态，相互独立，不存在先后依赖关系
  - M-PRD-11 构建结果验证：本模块产出的结构化知识对象是验证的检测对象之一，验证逻辑由 M-PRD-11 负责
  - M-PRD-9 质检与治理（二期）：本模块产出的结构化知识对象将作为二期质检的输入，质检逻辑不在本模块实现

## 3. 使用场景

### 3.1 场景一：AI 辅助抽取问答对

- **场景描述**：知识运营人员从标准化文档候选集中选择若干文档，触发 AI 从中自动抽取问答对，形成问答库的结构化知识对象草稿，人工审核后启用
- **触发角色**：知识运营人员（也可由知识运营 Agent 在授权下触发）
- **前置条件**：项目方案已启用，且项目方案中存在知识形态为"问答库"的知识类目；标准化文档候选集中至少存在一份标准化文档
- **预期结果**：系统生成若干问答对草稿，知识运营人员可对草稿进行人工审核和编辑，确认后将问答对状态更新为"启用"

### 3.2 场景二：人工创建问答对

- **场景描述**：知识运营人员手动创建一条或多条问答对，直接填写问题、标准答案及来源
- **触发角色**：知识运营人员
- **前置条件**：项目方案已启用，且项目方案中存在知识形态为"问答库"的知识类目
- **预期结果**：问答对创建成功，状态为"启用"，关联到指定知识类目

### 3.3 场景三：AI 辅助抽取术语条目

- **场景描述**：知识运营人员从标准化文档候选集中选择若干文档，触发 AI 从中自动识别行业术语及其释义，生成术语条目草稿，人工审核后启用
- **触发角色**：知识运营人员（也可由知识运营 Agent 在授权下触发）
- **前置条件**：项目方案已启用，且项目方案中存在知识形态为"术语"的知识类目；标准化文档候选集中至少存在一份标准化文档
- **预期结果**：系统生成若干术语条目草稿，知识运营人员可对草稿进行审核和编辑，确认后将术语条目状态更新为"启用"

### 3.4 场景四：人工创建术语条目

- **场景描述**：知识运营人员手动创建一条术语条目，填写术语名称、释义、别名及来源
- **触发角色**：知识运营人员
- **前置条件**：项目方案已启用，且项目方案中存在知识形态为"术语"的知识类目
- **预期结果**：术语条目创建成功，状态为"启用"，关联到指定知识类目

### 3.5 场景五：编辑已有结构化知识对象

- **场景描述**：知识运营人员发现某条问答对的标准答案有误，或某条术语的释义不准确，进行人工修正
- **触发角色**：知识运营人员
- **前置条件**：结构化知识对象已存在，状态为"启用"或"停用"
- **预期结果**：编辑成功，更新后的结构化知识对象信息立即生效

### 3.6 场景六：停用结构化知识对象

- **场景描述**：知识运营人员发现某条问答对不再适用，将其停用，不再纳入知识包
- **触发角色**：知识运营人员
- **前置条件**：该结构化知识对象当前状态为"启用"
- **预期结果**：该结构化知识对象状态变为"停用"，不再被纳入新的知识包

### 3.7 异常/边界场景：项目方案中无匹配知识形态

- **场景描述**：知识运营人员进入结构化知识构建页面，但当前项目方案中未定义任何知识形态为"问答库"或"术语"的知识类目
- **触发角色**：知识运营人员
- **前置条件**：项目方案已启用，但未配置问答库或术语类目
- **预期结果**：系统提示"当前项目方案中未配置问答库或术语知识形态，请先在项目方案中添加对应知识类目"，不允许构建

## 4. 核心对象

> 仅写业务对象，不写数据库表、英文字段名、SQL、接口路径。

| 对象 | 是否新对象 | 对象说明 | 关键属性（中文） | 关联状态/关系 |
|------|------------|----------|-----------------|---------------|
| 结构化知识对象（问答对） | 否 | 以问题 + 标准答案为基本结构的结构化知识结果，知识形态为"问答库" | 问题表述（主问题）、标准答案、相似问题（可选）、所属知识类目、来源标准化文档（可选）、创建方式（AI抽取/人工创建）、启用状态 | 归属于知识类目；N:1 关联知识类目；可追溯到来源标准化文档 |
| 结构化知识对象（术语条目） | 否 | 以术语名称 + 释义为基本结构的结构化知识结果，知识形态为"术语" | 术语名称（首选词）、释义、别名/同义词（可选）、所属知识类目、来源标准化文档（可选）、创建方式（AI抽取/人工创建）、启用状态 | 归属于知识类目；N:1 关联知识类目；可追溯到来源标准化文档 |
| 标准化文档 | 否 | M-PRD-6 输出的统一处理对象，是本模块的候选输入来源 | 文档标题、文件类型、所属项目知识空间 | 被本模块引用为来源；1:N 关联结构化知识对象 |
| 知识形态 | 否 | 目标知识的组织形式，是构建的首要决策维度 | 形态名称、形态类型 | 关系：1:1 知识类目（在同一项目方案内） |
| 知识类目 | 否 | 用于承载某一类目标知识内容的配置项 | 类目名称、层级 | 关系：1:1 知识形态（在同一项目方案内） |
| 来源追溯关系 | 否 | 结构化知识对象与其来源标准化文档之间的可追溯关系 | 来源标准化文档引用、来源段落/章节（可选） | 归属于结构化知识对象 |

### 4.1 对象约束补充

- **结构化知识对象（问答对）的唯一性规则**：同一知识类目内，主问题表述不得完全重复。
- **结构化知识对象（术语条目）的唯一性规则**：同一知识类目内，术语首选词不得重复。
- **结构化知识对象的归属关系**：每个结构化知识对象归属于且仅归属于一个知识类目，不可无类目创建。
- **知识类目可用条件**：仅当项目方案已启用，且知识类目的知识形态为"问答库"或"术语"时，本模块才允许在该类目下进行构建。
- **来源追溯关系的可选性**：人工直接创建的结构化知识对象允许不填写来源标准化文档；AI 抽取的结构化知识对象应默认关联抽取来源的标准化文档。

## 5. 业务事实归属与状态一致性

### 5.1 业务事实归属（Source of Truth）

- **某个结构化知识对象是否处于启用状态**的唯一事实来源是：该结构化知识对象自身的启用状态属性。
- **[某个结构化知识对象归属哪个知识类目与知识形态]** 的唯一事实来源是：结构化知识对象本身的属性记录。
- **某个结构化知识对象的来源标准化文档是哪份**的唯一事实来源是：该结构化知识对象的来源追溯关系。
- **当前项目应构建哪些知识类目及其知识形态**的唯一事实来源是：项目方案对象（由 M-PRD-4 定义）。

### 5.2 状态一致性要求

- 本文档涉及的对象状态必须与《概念模型 V4.2》一致。
- 结构化知识对象的状态有且仅有"启用"和"停用"两种，与《概念模型 V4.2》保持一致。
- 不允许在正文、伪代码、验收标准中出现相互冲突的状态名。
- AI 抽取后生成的草稿在人工审核确认前，状态默认为"停用"；人工确认启用后，状态更新为"启用"。

## 7. 详细功能需求


### 7.1 功能点一：构建目标选择（先形态，后类目）

#### 功能描述
在启动结构化知识构建前，知识运营人员必须先明确要构建的知识形态，再选择具体的知识类目，从而确定本次构建的目标。

#### 触发角色
- 知识运营人员

#### 前置条件
- 项目知识空间已创建，且当前项目方案已生效。
- 项目方案中至少配置了一个属于结构化通道的知识形态（问答库 或 术语）。

#### 输入
- 用户的选择操作。

#### 正常流程
1. 系统展示当前阶段支持的结构化知识形态选项（问答库、术语）。
2. 用户选择某一目标知识形态（如：问答库）。
3. 系统读取当前项目方案，筛选出配置为该知识形态的所有知识类目。
4. 系统以下拉列表或树状结构展示这些匹配的知识类目。
5. 用户选择具体的目标知识类目。

#### 异常/拦截
- 当 [项目方案中未配置任何结构化知识形态] 时，系统应：拦截操作，提示"当前项目方案未包含结构化知识目标，请先完善项目方案"。
- 当 [用户选定知识形态后，发现项目方案中无对应类目] 时，系统应：置空类目选择器，并提示"当前方案下无对应此形态的知识类目"。

#### 输出结果
- 确定的构建目标组合：[知识形态 + 知识类目]。

#### 状态变化
- 无对象状态变化，仅为前端会话状态。

#### 业务规则
- **形态优先规则**：必须先选择知识形态，知识类目选择器才能激活。
- **联动过滤规则**：知识类目列表必须严格受限于已选的知识形态，仅展示 1:1 映射关系匹配的类目。

#### 与其他模块的边界/影响
- 本功能依赖 M-PRD-4（项目方案配置）提供的映射数据。

### 7.2 功能点二：AI 辅助抽取问答对

#### 功能描述

知识运营人员在确定构建目标后，从标准化文档候选集中选择一份或多份标准化文档，触发 AI 自动从中抽取问答对草稿，形成待审核的结构化知识对象列表。

#### 触发角色

- 知识运营人员（主动触发）或知识运营 Agent（授权执行）

#### 前置条件

- 已完成功能点一（选定知识形态与知识类目）。
- 标准化处理已完成，存在标准化文档候选集。

#### 输入

- 被选择的标准化文档（一份或多份）
- 当前知识形态与类目

#### 正常流程

1. 知识运营人员在 AI 抽取设置页面选择标准化文档范围
2. 知识运营人员点击"开始抽取"，系统调用问题抽取工具和答案抽取工具
3. 系统从选定的标准化文档中抽取问题表述与对应答案
4. 系统生成问答对草稿，每条草稿默认状态为"停用"
5. 系统在草稿预览页展示抽取结果，标注来源标准化文档
6. 知识运营人员逐条或批量审核草稿，确认的草稿状态更新为"启用"，驳回的草稿予以删除或标记忽略

#### 异常/拦截

- 当选定文档数量为零时，系统应拦截并提示"请至少选择一份标准化文档"
- 当 AI 抽取任务执行失败时，系统应给出明确失败提示，并保留任务发起记录，允许重新触发
- 当 AI 抽取结果为空时，系统应提示"未从所选文档中抽取到问答对，请检查文档内容或换用其他文档"

- 审核确认后的问答对（状态更新为"启用"）
- 每条问答对自动关联来源标准化文档

#### 状态变化

- 审核确认后：由"停用"变为"启用"
- 驳回的草稿：删除

#### 业务规则

- AI 抽取结果为草稿，不自动启用，必须经知识运营人员审核确认后方可启用
- AI 抽取的问答对应自动记录来源标准化文档，实现来源追溯

#### 与其他模块的边界/影响

- 本功能不负责：标准化文档的生成（由 M-PRD-6 负责）

```text
2. 若 不存在，则返回 提示"该对象不存在"；
3. 判断 当前状态与目标操作是否一致；
4. 若 已处于目标状态，则返回 提示"该对象已处于[启用/停用]状态"；
5. 将 结构化知识对象 从 当前状态 更新为 目标状态；
6. 返回 成功结果。
```

### 8.6 异常流程：项目方案无匹配知识形态

```text
当 知识运营人员 进入结构化知识构建主页 时，系统执行：
1. 读取 当前项目方案；
2. 筛选 知识形态为"问答库"或"术语"的知识类目；
3. 若 筛选结果为空，则：
   4. 提示 "当前项目方案中未配置问答库或术语知识形态，请先在项目方案中添加对应知识类目"；
   5. 页面不展示构建入口；
6. 若 筛选结果不为空，则正常展示知识类目列表，进入构建流程。
```

## 10. 异常与边界情况

| 场景 | 触发条件 | 处理方式 | 用户提示 |
|------|----------|----------|----------|
| 项目方案为停用状态 | 进入本模块时项目方案已停用 | 拦截所有构建操作 | "当前项目方案已停用，不可进行知识构建" |
| 项目方案无匹配知识形态 | 项目方案中无"问答库"或"术语"类目 | 不展示构建入口，展示引导提示 | "当前项目方案中未配置问答库或术语知识形态，请先在项目方案中添加对应知识类目" |
| 标准化文档候选集为空 | 触发 AI 抽取时，项目内无标准化文档 | 拦截抽取操作 | "当前项目无可用标准化文档，请先完成标准化处理" |
| AI 抽取任务失败 | 抽取过程中发生执行错误 | 保留任务记录，提示重新触发 | "AI 抽取执行失败，请重新触发" |
| AI 抽取结果为空 | 选定文档中未抽取到内容 | 提示无结果，不生成草稿 | "未从所选文档中抽取到问答对/术语，请检查文档内容或换用其他文档" |
| 必填字段为空 | 创建/编辑时主问题、标准答案、术语名称、释义为空 | 拦截操作 | "[字段名]不可为空" |
| 问答对主问题重复 | 同类目内已存在相同主问题 | 提示确认，不强制拦截 | "该类目下已存在相同的主问题，是否确认创建" |
| 术语首选词重复 | 同类目内已存在相同首选词 | 强制拦截 | "该类目下已存在同名术语，请修改术语名称或合并到已有术语" |
| 对象已处于目标状态 | 对已启用对象执行启用，或对已停用对象执行停用 | 提示当前已是目标状态 | "该对象已处于[启用/停用]状态" |
| 删除已纳入启用知识包的对象 | 被删对象已被 M-PRD-10 纳入当前启用知识包 | 提示确认，允许确认后删除 | "该对象已被纳入当前启用知识包，删除后知识包中的引用将失效，是否确认删除" |
| 并发编辑同一结构化知识对象 | 两人同时编辑同一对象 | 以后提交者为准，提示冲突 | "该对象已被其他运营人员修改，请刷新后重试" |

### 10.1 特殊边界补充

- **结构化通道与非结构化切片通道并行**：本模块可与 M-PRD-8 同时对同一份标准化文档执行不同知识形态的构建，两者相互独立，不存在先后依赖。
- **同一份标准化文档多类目支撑**：一份标准化文档可同时作为多个知识类目（含不同类型的知识形态）的构建输入来源。
- **草稿与启用对象共存**：同一知识类目下，可同时存在状态为"停用"（草稿或被停用）和"启用"的对象。
- **项目方案变更不自动重建**：若项目方案中的知识类目或知识形态被 M-PRD-4 调整后，已生成的结构化知识对象不自动改写，是否重建由知识运营明确确认。

## 13. 依赖与约束

### 13.1 业务依赖

- 本模块依赖 M-PRD-4 项目方案配置 输出的已启用项目方案（包含知识类目 + 知识形态定义），是本模块启动的前置条件
- 本模块依赖 M-PRD-6 标准化处理 输出的标准化文档候选集，作为 AI 抽取的候选输入范围
- 本模块的输出（状态为"启用"的结构化知识对象）是 M-PRD-10 知识包管理的直接输入来源之一

### 13.2 业务约束

- 一期仅支持"问答库"和"术语"两种知识形态的结构化知识构建
- 结构化通道与非结构化切片通道相互独立，不存在先后依赖，可并行执行
- 结构化知识对象不依赖知识切片作为前置
- 项目方案中的知识类目或知识形态调整后，已生成的结构化知识对象不自动改写，是否重建由知识运营明确确认（依据 R-M-PRD-4-06）
- 工具配置（如 AI 抽取工具的参数配置）为二期能力，一期不要求工具参数的正式配置与回写

### 13.3 外部影响说明

- 本模块的输出会影响：M-PRD-10 知识包管理（结构化知识对象是知识包的组成来源之一）、M-PRD-11 构建结果验证（结构化知识对象是验证的对象之一）
- 本模块依赖的共享规则包括：《概念模型 V4.2》中的对象定义与状态定义、《角色矩阵与权限边界 V3.2》中的知识运营人员与知识运营 Agent 的权限定义
