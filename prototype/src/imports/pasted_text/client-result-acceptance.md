## 1. 模块定位

### 1.1 一句话定位

为企业客户提供知识包查看与验收确认能力，完成项目知识工程结果的最终确认与反馈。

### 1.2 模块价值

- **对企业客户**：提供清晰的知识成果查看入口，确认交付内容是否符合预期
- **对知识运营**：获取客户对知识包结果的确认反馈，作为项目交付依据
- **对平台**：建立标准化的结果交付与验收通道，形成闭环

### 1.3 本模块负责

- 企业客户查看项目知识包内容
- 企业客户提交验收确认
- 企业客户提交结果反馈

### 1.4 本需求不做

- 知识构建执行
- 质检配置与执行
- 模板管理
- 工具配置
- 项目方案配置
- 文件上传（由 C-PRD-1 负责）

### 1.5 上下游边界

- **上游输入**：知识包对象（来自 M-PRD-10 知识包管理）
- **下游输出**：验收结果、反馈记录
- **与其他模块的关系**：
  - M-PRD-10 知识包管理：提供可供验收的知识包
  - M-PRD-11 构建结果验证：验收前的可用性验证（管理端）
  - C-PRD-1 文件上传：企业客户前期上传原始材料

## 3. 使用场景

### 3.1 场景一：企业客户查看知识包结果

- **场景描述**：企业客户查看项目中已构建完成的知识包内容
- **触发角色**：企业客户
- **前置条件**：
  - 项目知识空间已创建
  - 知识包已构建完成并可供查看
  - 企业客户已获得项目访问权限
- **预期结果**：展示知识包内容概要，支持浏览知识包内结构化知识对象和/或知识切片

### 3.2 场景二：企业客户提交验收确认

- **场景描述**：企业客户对知识包结果进行验收确认
- **触发角色**：企业客户
- **前置条件**：
  - 知识包已可供验收
  - 企业客户已查看知识包内容
- **预期结果**：验收状态更新为"已验收"，记录验收时间与验收人

### 3.3 场景三：企业客户提交结果反馈

- **场景描述**：企业客户对知识包结果提出修改意见或反馈
- **触发角色**：企业客户
- **前置条件**：
  - 知识包已可供验收
  - 企业客户已查看知识包内容
- **预期结果**：反馈记录创建，知识运营人员可在管理端查看

### 3.4 异常/边界场景：知识包不可用

- **场景描述**：企业客户尝试查看尚未构建完成或已停用的知识包
- **触发角色**：企业客户
- **前置条件**：知识包处于不可用状态
- **预期结果**：系统提示知识包暂不可用或已停用

## 4. 核心对象

| 对象     | 是否新对象 | 对象说明                       | 关键属性（中文）                                             | 关联状态/关系                                     |
| -------- | ---------- | ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------- |
| 知识包   | 否         | 项目最终交付的知识结果集合     | 知识包名称、项目知识空间、启用状态、包含的知识对象类型、创建时间 | 归属项目知识空间，包含结构化知识对象和/或知识切片 |
| 验收结果 | 是         | 企业客户对知识包的验收确认记录 | 验收人、验收时间、验收状态、项目知识空间、知识包             | 归属项目知识空间，关联知识包                      |
| 反馈记录 | 是         | 企业客户提交的结果反馈意见     | 反馈人、反馈时间、反馈内容、反馈类型、项目知识空间、知识包   | 归属项目知识空间，关联知识包                      |

### 4.1 对象约束补充

- **知识包的唯一性规则**：同一项目知识空间可存在多个知识包，按启用状态区分当前可用知识包
- **验收结果的归属关系**：验收结果归属项目知识空间，关联知识包，记录验收人信息
- **反馈记录的可用条件**：知识包处于可验收状态时，企业客户可提交反馈

## 5. 业务事实归属与状态一致性

### 5.1 业务事实归属

- **验收状态的唯一事实来源**：验收结果对象中的"验收状态"字段

### 5.2 状态一致性要求

- 验收状态包括：待验收、已验收、已反馈
- 知识包状态与《概念模型》保持一致
- 状态命名全文统一，不出现冲突

## 7. 详细功能需求

### 7.1 功能点一：知识包查看

**功能描述**
企业客户查看项目中已构建完成的知识包内容及概要信息。

**触发角色**
企业客户

**前置条件**

- 企业客户已登录
- 企业客户具有该项目访问权限
- 知识包已构建完成并处于可用状态

**输入**

- 项目知识空间 ID
- 知识包 ID（可选，默认查看当前启用知识包）

**正常流程**

1. 企业客户进入知识包查看页面
2. 系统查询该企业客户有权限的项目知识空间
3. 查询该项目下可用的知识包
4. 展示知识包概要信息（名称、包含的知识对象类型、创建时间等）
5. 支持浏览知识包内的结构化知识对象和/或知识切片内容

**异常/拦截**

- 当知识包不存在时，系统应：提示"知识包不存在"
- 当知识包已停用时，系统应：提示"该知识包已停用"
- 当知识包尚未构建完成时，系统应：提示"知识包构建中，请稍后查看"
- 当企业客户无项目访问权限时，系统应：拦截访问，提示权限不足

**输出结果**

- 知识包概要信息
- 知识包内容浏览界面

**状态变化**

- 无状态变化（仅查看）

**业务规则**

- 仅展示企业客户有权限查看的知识包
- 默认展示当前启用的知识包
- 支持查看历史知识包（如有）

**与其他模块的边界/影响**

- 本功能不负责：知识包构建、知识包配置
- 本功能对下游无直接影响
- 知识包内容由 M-PRD-10 知识包管理提供

------

### 7.2 功能点二：验收确认提交

**功能描述**
企业客户对知识包结果进行验收确认，记录验收状态。

**触发角色**
企业客户

**前置条件**

- 企业客户已登录
- 企业客户具有该项目访问权限
- 知识包处于可验收状态
- 企业客户尚未提交过验收确认（或允许重新验收）

**输入**

- 项目知识空间 ID
- 知识包 ID
- 验收确认操作（确认/不确认）

**正常流程**

1. 企业客户进入验收确认页面
2. 系统展示知识包概要及验收说明
3. 企业客户选择验收确认操作
4. 系统创建或更新验收结果记录
5. 更新验收状态为"已验收"
6. 返回验收成功提示

**异常/拦截**

- 当知识包不可验收时，系统应：提示"该知识包暂不可验收"
- 当企业客户无项目访问权限时，系统应：拦截操作，提示权限不足
- 当验收已提交且不允许修改时，系统应：提示"验收已提交，不可修改"

**输出结果**

- 验收成功/失败提示
- 验收结果记录 ID

**状态变化**

- 验收结果：由"待验收"变为"已验收"

**业务规则**

- 验收确认需记录验收人、验收时间
- 支持重新验收（如业务允许）
- 验收状态变更需记录操作日志

**与其他模块的边界/影响**

- 本功能不负责：知识包构建、质检执行
- 本功能对下游的输出是：验收结果记录
- 管理端可查看验收状态，用于项目交付判断

------

### 7.3 功能点三：反馈提交

**功能描述**
企业客户对知识包结果提交修改意见或反馈意见。

**触发角色**
企业客户

**前置条件**

- 企业客户已登录
- 企业客户具有该项目访问权限
- 知识包处于可验收状态

**输入**

- 项目知识空间 ID
- 知识包 ID
- 反馈内容
- 反馈类型（可选）

**正常流程**

1. 企业客户进入反馈提交页面
2. 系统展示反馈填写表单
3. 企业客户填写反馈内容
4. 系统校验反馈内容非空
5. 创建反馈记录
6. 返回反馈提交成功提示

**异常/拦截**

- 当反馈内容为空时，系统应：提示"请填写反馈内容"
- 当知识包不可验收时，系统应：提示"该知识包暂不可提交反馈"
- 当企业客户无项目访问权限时，系统应：拦截操作，提示权限不足

**输出结果**

- 反馈提交成功/失败提示
- 反馈记录 ID

**状态变化**

- 验收结果：可由"待验收"变为"已反馈"（如业务定义）

**业务规则**

- 反馈内容需记录反馈人、反馈时间
- 支持多次提交反馈
- 反馈类型可分类（如：内容问题、格式问题、其他）

**与其他模块的边界/影响**

- 本功能不负责：反馈处理、问题修复
- 本功能对下游的输出是：反馈记录
- 管理端可查看反馈内容，用于后续优化

## 8. 自然语言伪代码

### 8.1 主流程：知识包查看流程

当企业客户执行知识包查看时，系统执行：

1. 校验企业客户是否已登录；
2. 若未登录，则返回"请先登录"提示；
3. 校验企业客户是否具有该项目知识空间访问权限；
4. 若权限不足，则返回"无项目访问权限"提示；
5. 查询该项目下可用的知识包；
6. 若知识包不存在，则返回"知识包不存在"提示；
7. 若知识包已停用，则返回"该知识包已停用"提示；
8. 若知识包尚未构建完成，则返回"知识包构建中，请稍后查看"提示；
9. 展示知识包概要信息及内容；
10. 返回查看成功结果。

### 8.2 主流程：验收确认提交流程

当企业客户执行验收确认提交时，系统执行：

1. 校验企业客户是否已登录；
2. 若未登录，则返回"请先登录"提示；
3. 校验企业客户是否具有该项目知识空间访问权限；
4. 若权限不足，则返回"无项目访问权限"提示；
5. 校验知识包是否处于可验收状态；
6. 若不可验收，则返回"该知识包暂不可验收"提示；
7. 校验是否允许重新验收（如已提交过）；
8. 若不允许修改且已提交，则返回"验收已提交，不可修改"提示；
9. 创建或更新验收结果记录，记录验收人、验收时间；
10. 更新验收状态为"已验收"；
11. 返回验收成功结果。

### 8.3 主流程：反馈提交流程

当企业客户执行反馈提交时，系统执行：

1. 校验企业客户是否已登录；
2. 若未登录，则返回"请先登录"提示；
3. 校验企业客户是否具有该项目知识空间访问权限；
4. 若权限不足，则返回"无项目访问权限"提示；
5. 校验知识包是否处于可验收状态；
6. 若不可验收，则返回"该知识包暂不可提交反馈"提示；
7. 校验反馈内容是否非空；
8. 若内容为空，则返回"请填写反馈内容"提示；
9. 创建反馈记录，记录反馈人、反馈时间、反馈内容；
10. 更新验收状态为"已反馈"（如业务定义）；
11. 返回反馈提交成功结果。

### 8.4 异常流程：知识包不可用处理

当发生知识包不可用异常时，系统执行：

1. 判断不可用原因（不存在、已停用、构建中）；
2. 根据原因返回对应的明确提示；
3. 阻止查看或验收操作；
4. 保持对象状态不变。

## 10. 异常与边界情况

| 场景         | 触发条件               | 处理方式                       | 用户提示               |
| ------------ | ---------------------- | ------------------------------ | ---------------------- |
| 输入为空     | 反馈内容为空           | 拦截提交                       | "请填写反馈内容"       |
| 输入非法     | 知识包 ID 无效         | 拦截操作                       | "知识包不存在"         |
| 对象不存在   | 知识包不存在           | 拦截查看                       | "知识包不存在"         |
| 状态不合法   | 知识包已停用           | 拦截查看/验收                  | "该知识包已停用"       |
| 权限不足     | 企业客户无项目访问权限 | 拦截所有操作                   | "您无该项目访问权限"   |
| 重复操作     | 重复提交验收确认       | 根据业务规则决定是否允许       | "验收已提交"或允许更新 |
| 并发冲突     | 多人同时提交验收       | 分别记录，以最新为准或限制单人 | "验收提交成功"         |
| 引用关系冲突 | 项目被删除后查看       | 拦截查看                       | "项目已不存在"         |

### 10.1 特殊边界补充

- **多次反馈**：支持企业客户多次提交反馈，每次独立记录
- **验收修改**：如业务允许，支持企业客户修改已提交的验收确认
- **历史知识包**：支持查看历史版本知识包（如有多版本管理）

## 13. 依赖与约束

### 13.1 业务依赖

- 依赖项目知识空间已创建
- 依赖知识包已构建完成并可供查看
- 依赖企业客户具有项目访问权限

### 13.2 业务约束

- 企业客户不参与知识构建过程
- 验收结果不是审批流，仅作为客户确认记录
- 反馈不强制要求，企业客户可选择不提交

### 13.3 外部影响说明

- 本模块的输出会影响：知识运营人员在管理端的项目交付判断
- 本模块依赖的共享规则包括：角色权限规则、知识包启用规则
