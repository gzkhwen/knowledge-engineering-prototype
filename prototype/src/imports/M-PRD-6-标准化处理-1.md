## 1. 模块定位

### 1.1 一句话定位

对项目知识空间中已接入的原始材料执行解析、清洗、转换、治理，将其转化为结构统一、来源可追溯的标准化文档，作为后续知识构建的统一输入基础。

### 1.2 模块价值

原始材料来自企业客户上传，格式多样、质量参差不齐，无法直接用于知识构建。标准化处理是知识工程链路的第一道核心转化环节，解决"原始材料进不来、进来用不了"的问题，为结构化知识构建通道和非结构化切片构建通道提供统一、可信、可追溯的输入基础，是保障后续知识结果质量的前提。

### 1.3 本模块负责

- 对已接入的原始材料执行文件解析（含文字提取、版面分析、表格识别）
- 对解析结果执行清洗（去页眉页脚、去页码、去重复内容、特殊字符清洗）
- 对内容进行格式转换（统一为标准文档格式）
- 写入来源追溯信息（保留原始材料来源、文件名、处理时间等元数据）
- 生成标准化文档，形成标准化文档候选集，供后续知识类目选择使用
- 支持知识运营人员查看标准化处理结果与处理状态（含摘要与全文预览）
- 支持对处理失败或未被引用的原始材料进行重新处理触发
- 支持停用标准化文档（不物理删除）
- 提供后续结构化或非结构化知识构建的快捷入口

### 1.4 本需求不做

- 结构化知识对象的抽取与构建（由 M-PRD-7 负责）
- 知识切片的生成（由 M-PRD-8 负责）
- 判断某段标准化内容属于哪个知识类目（由知识类目选择环节在 M-PRD-4/M-PRD-7/M-PRD-8 中处理）
- 质检与冲突检测（由 M-PRD-9 二期负责）
- 对处理结果直接组织为知识包
- 网页采集内容治理、数据库源治理（一期暂不建设；三期扩展）
- 工具配置参数的持久化回写到项目方案（二期能力）
- 模板中工具配置的继承与复用（二期能力）

### 1.5 上下游边界

- **上游输入**：原始材料（来自 M-PRD-5 原始材料接入与管理，一期以文件上传为主）
- **下游输出**：标准化文档候选集，供 M-PRD-7 结构化知识构建、M-PRD-8 非结构化切片构建消费
- **与其他模块的关系**：
  - **M-PRD-5 原始材料接入与管理**：本模块以 M-PRD-5 中的原始材料为输入，不负责原始材料的上传与接入管理
  - **M-PRD-4 项目方案配置**：本模块执行标准化处理，不判断内容所属知识类目；类目归属由 M-PRD-4/M-PRD-7/M-PRD-8 在选择候选内容阶段确定
  - **M-PRD-7 结构化知识构建**：标准化文档是结构化通道的统一输入基础，本模块提供跳转入口但不参与结构化构建执行
  - **M-PRD-8 非结构化切片构建**：标准化文档是切片通道的统一输入基础，本模块提供跳转入口但不参与切片构建执行
  - **M-PRD-9 质检与治理**：质检属于二期能力，本模块不承担结果质量判定职责

## 3. 使用场景

### 3.1 场景一：知识运营人员触发单批次标准化处理

- **场景描述**：知识运营人员在完成项目方案初始化后，对已上传的原始材料批量触发标准化处理，将其转化为标准化文档以进入后续知识构建流程。
- **触发角色**：知识运营人员
- **前置条件**：项目知识空间处于启用状态；项目方案已存在（至少包含知识类目与知识形态）；待处理原始材料已接入且存在。
- **预期结果**：原始材料经解析、清洗、转换、元数据写入后，生成对应的标准化文档；标准化文档进入标准化文档候选集，状态为启用；处理结果可在管理界面查看。

### 3.2 场景二：知识运营人员查看标准化处理结果

- **场景描述**：知识运营人员在标准化处理完成后，对处理结果进行查阅，了解哪些原始材料已成功处理、哪些处理失败或存在内容异常，以判断是否需要重新处理或调整材料。
- **触发角色**：知识运营人员
- **前置条件**：标准化处理已执行，至少存在部分处理结果。
- **预期结果**：知识运营人员可查看每份原始材料的处理状态、处理方式、生成的标准化文档内容摘要（前500字）及来源追溯信息；支持点击全文预览；可识别处理失败的原始材料及失败原因。

### 3.3 场景三：对处理失败或未被引用的原始材料重新触发标准化处理

- **场景描述**：某些原始材料因文件损坏、格式不支持或解析异常等原因导致标准化处理失败，或者处理成功但尚未被下游知识结果引用，知识运营人员在查阅后重新触发处理。
- **触发角色**：知识运营人员
- **前置条件**：原始材料存在处理失败记录，或已生成的标准化文档**未被下游任何知识结果引用**。
- **预期结果**：系统重新对该原始材料执行标准化处理流程；若处理成功，生成新的标准化文档并更新状态，覆盖旧版；若仍失败，保留失败记录并给出原因说明。

### 3.4 场景四：停用标准化文档

- **场景描述**：知识运营人员发现某份标准化文档内容已过期或存在质量问题，决定将其停用，以避免其内容被后续知识构建使用。
- **触发角色**：知识运营人员
- **前置条件**：标准化文档处于启用状态。
- **预期结果**：标准化文档状态变为停用；停用后的标准化文档不再出现在后续知识类目选择的候选范围内；已基于该标准化文档生成的知识结果不自动撤销，由知识运营人员明确确认是否处理。

### 3.5 场景五：发起知识构建

- **场景描述**：标准化处理完成后，知识运营人员直接在列表选中一份或多份标准化文档，发起后续的知识构建流程。
- **触发角色**：知识运营人员
- **前置条件**：选中的标准化文档处于启用状态。
- **预期结果**：系统引导用户首先选择"知识类目"，再根据选中的类目选择对应的"知识形态"，随后携带所选的标准化文档跳转至对应的知识构建通道（结构化或非结构化）。

### 3.6 异常/边界场景：上传文件格式不支持或文件损坏

- **场景描述**：企业客户上传的文件格式不在一期支持范围内（仅支持 txt, word, excel, markdown），或文件已损坏无法解析，或处理超时。
- **触发角色**：知识运营人员（查阅处理状态后发现）
- **前置条件**：原始材料已接入，触发标准化处理后失败或超时。
- **预期结果**：系统返回处理失败状态及明确原因（格式不支持、文件损坏或处理超时）；该原始材料不生成标准化文档；知识运营人员可据此通知企业客户重新提供。

## 4. 核心对象

> 仅写业务对象，不写数据库表、英文字段名、SQL、接口路径。

| 对象 | 是否新对象 | 对象说明 | 关键属性（中文） | 关联状态/关系 |
|------|------------|----------|-----------------|---------------|
| 原始材料 | 否 | 由 M-PRD-5 管理，本模块以其为输入 | 文件名、来源类型、上传时间、文件格式 | 1:1 对应一份标准化文档 |
| 标准化文档 | 否 | 原始材料经标准化处理后生成的统一处理对象，是后续知识构建的直接输入基础 | 来源原始材料引用、处理时间、文件格式来源、版面类型标注、内容摘要、来源追溯信息、当前状态 | 启用 / 停用；1:1 对应原始材料 |
| 标准化文档候选集 | 否 | 当前项目空间内所有处于启用状态的标准化文档集合，构成后续知识构建的候选输入范围 | 所属项目知识空间、包含的标准化文档列表 | 由所有启用状态的标准化文档动态构成 |
| 标准化处理 | 否 | 将原始材料解析、清洗、转换、治理并生成标准化文档的处理过程 | 处理触发时间、处理状态（待处理 / 处理中 / 已完成 / 失败）、处理方式记录、失败原因 | 过程对象，不单独定义复杂状态机；结果体现在标准化文档上 |
| 来源追溯关系 | 否 | 标准化文档与来源原始材料之间的可追溯关系 | 原始材料引用、处理时间、处理方式概要 | 归属于标准化文档 |

### 4.1 对象约束补充

- **标准化文档的唯一性规则**：默认一份原始材料对应一份标准化文档；重新处理后，原有标准化文档被新版本覆盖，旧版不保留（一期不做多版本管理）。
- **标准化文档候选集的构成规则**：候选集动态构成，仅包含当前项目空间内处于启用状态的标准化文档；停用的标准化文档自动移出候选集。
- **标准化处理的归属关系**：标准化处理过程归属于所在项目知识空间，不跨项目共用。
- **来源追溯的可用条件**：来源追溯信息在标准化文档生成时写入，并随标准化文档生命周期保持不变。

## 5. 业务事实归属与状态一致性

### 5.1 业务事实归属

- **某份原始材料对应哪份标准化文档**的唯一事实来源是：原始材料与标准化文档的映射关系（归属于标准化文档对象的来源引用属性）。
- **某份标准化文档是否可被后续知识构建使用**的唯一事实来源是：标准化文档对象的当前启用状态。
- **某份标准化文档来源于哪个原始材料、经过何种处理方式**的唯一事实来源是：标准化文档对象的来源追溯信息（即来源追溯关系）。
- **某份标准化文档是否被引用**的唯一事实来源是：下游结构化知识对象或非结构化切片中对该标准化文档的关联引用记录。

### 5.2 状态一致性要求

- 本模块涉及的标准化文档状态为：**启用 / 停用**，与《概念模型 V4.2》一致，不得在其他章节使用其他状态名。
- 标准化处理过程状态（待处理 / 处理中 / 已完成 / 失败）仅用于描述处理执行过程，不作为标准化文档的正式状态。
- 处理成功后，标准化文档默认状态为**启用**；处理失败时，不生成标准化文档对象，来源原始材料保留失败记录。

## 7. 详细功能需求

### 7.1 功能点一：触发标准化处理

#### 功能描述
知识运营人员在项目知识空间内，对一份或多份已接入的原始材料批量或逐一触发标准化处理，系统执行解析、清洗、转换、治理，生成对应的标准化文档。

#### 触发角色
- 知识运营人员
- 知识运营 Agent（在授权范围内触发）

#### 前置条件
- 所在项目知识空间处于启用状态。
- 项目方案已存在（至少包含知识类目与知识形态）。
- 被触发的原始材料已存在于当前项目知识空间，且当前不处于"处理中"状态。

#### 输入
- 触发对象：一份或多份原始材料。
- 处理方式：一期默认根据文件格式自动路由至适配的解析工具；不要求手动选择工具。

#### 正常流程
1. 知识运营人员在原始材料列表选择一份或多份原始材料，点击触发标准化处理。
2. 系统校验项目知识空间状态及项目方案前置条件。
3. 系统校验所选原始材料不处于"处理中"状态。
4. 系统根据文件格式自动匹配解析策略，启动异步处理流程。
5. 系统依次执行：文件解析 → 内容清洗 → 格式转换 → 来源追溯信息写入。
6. 处理成功后，生成标准化文档，状态设为启用，写入来源追溯信息。
7. 更新对应原始材料的处理状态为"已完成"，并关联至生成的标准化文档。
8. 标准化文档进入标准化文档候选集。

#### 异常/拦截
- 当项目知识空间处于停用状态时，拒绝触发，提示"当前项目空间已停用，无法执行处理"。
- 当项目方案不存在或未配置知识类目时，拒绝触发，提示"请先完成项目方案配置，再触发标准化处理"。
- 当所选原始材料中存在"处理中"状态的材料时，跳过该材料并提示"X 份材料正在处理中，已跳过"。
- 当文件格式不在一期支持范围内时（仅支持 txt, word, excel, markdown），对应原始材料标记处理失败，给出原因说明，不阻断其他材料。
- **超时机制**：标准化处理为异步任务，单份文件最大处理时长限制为 **30 分钟**。若超时未完成，系统自动将该任务的处理状态更新为"失败"，并记录失败原因为"处理超时"。

#### 输出结果
- 处理成功：生成标准化文档，状态为启用；原始材料处理状态更新为已完成。
- 处理失败：不生成标准化文档；原始材料处理状态更新为失败，记录失败原因。

#### 状态变化
- 原始材料：处理状态由"待处理"或"失败"更新为"处理中"，处理结束后更新为"已完成"或"失败"。
- 标准化文档：由无到有，初始状态为"启用"。

#### 业务规则
- 一期支持的处理类型以文件为主，**仅支持：纯文本（.txt）、Word（.docx/.doc）、Excel（.xlsx/.xls）、Markdown（.md）**。

### 7.2 功能点二：查看标准化处理状态与结果

#### 功能描述
知识运营人员可在项目知识空间内查看全部原始材料的处理状态，以及处理成功后生成的标准化文档内容摘要、全文和来源追溯信息。

#### 触发角色
- 知识运营人员

#### 前置条件
- 所在项目知识空间处于启用状态。

#### 正常流程
1. 知识运营人员进入原始材料与标准化文档管理页。
2. 系统展示原始材料列表及处理状态（待处理 / 处理中 / 已完成 / 失败）。
3. 对于"已完成"状态的原始材料，知识运营人员可点击查看单份标准化文档详情。
4. 详情页默认展示**内容摘要**（截取标准化后内容的前 500 字，以纯文本形式展示）、处理方式记录、来源追溯信息及当前状态。
5. 知识运营人员可点击**"全文预览"**按钮，系统在弹窗或新标签页中完整渲染并展示该标准化文档的全部内容。

#### 业务规则
- **内容摘要展示规则**：默认展示前 500 字纯文本，超出部分用省略号表示。
- **全文预览规则**：支持查看标准化转换后的完整文档内容，确保运营人员可核对解析准确性。

---

### 7.3 功能点三：重新触发标准化处理

#### 功能描述
对已标记为处理失败的原始材料，或已完成处理但**尚未被下游引用的**标准化文档对应的原始材料，知识运营人员可重新触发处理，覆盖旧版标准化文档。

#### 触发角色
- 知识运营人员

#### 前置条件
- 所在项目知识空间处于启用状态。
- 目标原始材料处于"失败"或"已完成"状态。
- **若处于"已完成"状态，其关联的标准化文档必须未被下游任何知识结果（结构化对象或切片）引用**。

#### 正常流程
1. 知识运营人员选择目标材料，触发"重新处理"操作。
2. 系统校验前置条件，特别是**引用状态校验**。
3. 若目标材料已有关联的标准化文档，系统提示：重新处理后，原有标准化文档将被覆盖，是否继续。
4. 确认后，系统启动重新处理流程。
5. 处理成功后，覆盖生成新的标准化文档（状态为启用），旧版不保留。

#### 异常/拦截
- 当目标原始材料处于"处理中"状态时，拒绝操作，提示"该材料正在处理中，请等待完成后再操作"。
- **当目标标准化文档已被下游知识结果引用时，系统拒绝操作，强拦截并提示："该标准化文档已被下游知识结果引用，无法重新处理。"**

#### 业务规则
- **重新处理限制**：标准化文档没有被下游任何结果引用的时候，才可以重新标准化。一旦被引用，为了保证下游数据血缘和知识溯源的稳定性，禁止重新处理。

---

### 7.4 功能点四：停用标准化文档

#### 功能描述
知识运营人员可将启用状态的标准化文档停用，使其退出后续知识构建的候选范围。

#### 触发角色
- 知识运营人员

#### 正常流程
1. 知识运营人员触发"停用"操作。
2. 系统提示确认：停用后该标准化文档将退出候选集，已有知识结果不自动撤销，是否继续。
3. 确认后，标准化文档状态从"启用"更新为"停用"，移出候选集。

---

### 7.5 功能点五：发起知识构建

#### 功能描述
提供从标准化处理结果到知识构建环节的快捷衔接入口。遵循"先选知识类目，再选知识形态"的逻辑，引导用户基于标准化文档快速启动知识构建。

#### 触发角色
- 知识运营人员

#### 前置条件
- 选中的标准化文档处于"启用"状态。

#### 正常流程
1. 知识运营人员在标准化文档列表勾选一份或多份状态为"启用"的标准化文档。
2. 点击列表上方的**"发起知识构建"**按钮。
3. 系统弹出构建配置引导窗：
   - 第一步：要求用户**选择知识类目**（下拉单选当前项目方案中已配置的类目）。
   - 第二步：根据所选类目，系统联动展示该类目下支持的**知识形态**（如 FAQ、术语、非结构化切片等），要求用户选择。
4. 用户确认选择后，系统携带所选的标准化文档ID、知识类目、知识形态参数，跳转至对应的知识构建工作台（M-PRD-7 或 M-PRD-8）。

#### 异常/拦截
- 当未选中任何文档或选中的文档包含"停用"状态时，拦截并提示"请选择处于启用状态的标准化文档"。

#### 业务规则
- **构建引导逻辑**：进行知识构建时，必须**首先选是什么知识（知识类目），然后才选什么形态（知识形态）**。

## 8. 自然语言伪代码

### 8.1 主流程：触发标准化处理

```text
当 知识运营人员触发原始材料的标准化处理时，系统执行：
1. 校验所在项目知识空间是否启用；
2. 若否，返回提示："当前项目空间已停用，无法执行处理"；
3. 校验项目方案是否配置知识类目与知识形态；
4. 若否，返回提示："请先完成项目方案配置，再触发标准化处理"；
5. 校验原始材料状态是否为"处理中"；若是则跳过；
6. 校验文件格式是否在支持列表（txt, word, excel, markdown）中；
7. 若不支持，标记处理状态为"失败"，记录原因"文件格式不支持"；
8. 对校验通过的材料，更新状态为"处理中"，启动异步处理（最大超时时间 30 分钟）；
9. 若 30 分钟内未完成，系统自动将状态更新为"失败"，记录原因"处理超时"；
10. 若处理成功，创建标准化文档（生成 500 字摘要），状态设为启用，更新原始材料状态为"已完成"。
```

### 8.2 异常流程：文件格式不支持或文件损坏

```text
当 发现文件格式不支持或文件损坏时，系统执行：
1. 判断文件格式是否为 txt, word, excel, markdown；
2. 若不在支持范围内，阻止处理，标记状态为"失败"，提示"文件格式不支持"；
3. 若文件损坏无法解析，标记状态为"失败"，提示"文件损坏或内容为空"；
4. 保持不生成标准化文档。
```

### 8.3 状态切换流程：停用标准化文档

```text
当 知识运营人员执行停用操作时，系统执行：
1. 校验当前文档是否为"启用"；
2. 若不满足，返回提示"该文档已停用"；
3. 将标准化文档状态更新为"停用"；
4. 返回停用成功。
```

### 8.4 状态切换流程：重新处理已完成材料

```text
当 知识运营人员触发重新处理时，系统执行：
1. 校验原始材料状态是否为"处理中"；若是，返回提示"正在处理中"；
2. 校验关联的标准化文档是否被下游知识结果引用；
3. 若已被引用，拦截操作并提示："该文档已被下游知识结果引用，无法重新处理"；
4. 若未被引用，提示用户覆盖风险；
5. 用户确认后，将状态重置为"处理中"，启动标准化处理；
6. 处理成功后覆盖旧文档。
```

### 8.5 主流程：发起知识构建

```text
当 知识运营人员点击"发起知识构建"时，系统执行：
1. 校验选中的标准化文档是否均处于"启用"状态；
2. 若包含停用文档，提示"请选择处于启用状态的标准化文档"；
3. 弹出选项要求用户首先选择"知识类目"；
4. 根据选中的知识类目，联动加载并要求用户选择"知识形态"；
5. 校验用户的类目与形态选择是否完整；
6. 若完整，携带选中数据跳转至对应的结构化/非结构化知识构建页面。
```

## 9. 关键业务规则

| 规则编号 | 规则内容 | 优先级 |
|----------|----------|--------|
| R-STD-01 | 标准化处理必须在项目方案已存在（至少包含知识类目与知识形态）的前提下触发 | 高 |
| R-STD-02 | 一份原始材料默认对应生成一份标准化文档 | 高 |
| R-STD-03 | 知识构建入口逻辑：必须先选择知识类目，再选择知识形态 | 高 |
| R-STD-04 | 一期仅支持 txt, word, excel, markdown 格式的标准化处理；不支持的格式直接返回失败 | 高 |
| R-STD-05 | 异步处理超时机制：单文件最大处理时长为 30 分钟，超时自动标记为失败 | 高 |
| R-STD-06 | 标准化文档候选集由所有处于启用状态的标准化文档动态构成 | 高 |
| R-STD-07 | 重新处理限制：标准化文档没有被下游任何结果引用的时候，才可以重新标准化 | 高 |
| R-STD-08 | 重新处理成功后，覆盖原有标准化文档内容，旧版不保留 | 中 |
| R-STD-09 | 处理失败时，不生成标准化文档对象，失败原因必须明确记录 | 高 |

## 10. 异常与边界情况

| 场景 | 触发条件 | 处理方式 | 用户提示 |
|------|----------|----------|----------|
| 项目空间停用时触发处理 | 项目知识空间状态为停用 | 拒绝触发 | "当前项目空间已停用，无法执行处理" |
| 原始材料处于"处理中"时再次触发 | 目标原始材料处理状态为处理中 | 跳过该材料 | "X 份材料正在处理中，已跳过" |
| 文件格式不支持 | 文件格式非 txt/word/excel/markdown | 标记失败 | "文件格式不支持（当前仅支持：txt, word, excel, markdown）" |
| 文件损坏或内容为空 | 文件无法打开或解析内容为空 | 标记失败 | "文件损坏或内容为空，无法解析" |
| 异步处理超时 | 处理时长超过 30 分钟 | 标记失败 | 状态变为失败，原因展示为"处理超时" |
| 重新处理已被引用的文档 | 标准化文档已被下游结果引用 | 拦截操作 | "该文档已被下游知识结果引用，无法重新处理" |

### 10.1 特殊边界补充

- **同一文件多次上传**：一期不做全局去重校验，每次上传视为独立原始材料，分别触发标准化处理。

## 13. 依赖与约束

### 13.1 业务依赖
- 依赖 M-PRD-4 项目方案配置提供知识类目与知识形态数据供"发起知识构建"使用。
- 依赖下游构建模块（M-PRD-7/8）提供引用关系状态查询，以判断是否允许重新处理。

### 13.2 业务约束
- 一期仅支持 txt, word, excel, markdown 四种格式。
- 标准化文档被引用后绝对禁止重新处理。

### 13.3 外部影响说明
- 本模块的输出会影响下游知识构建的输入质量。
- 强制要求先选类目再选形态，影响用户的操作路径习惯。
