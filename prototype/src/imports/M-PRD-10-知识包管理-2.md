## 1. 模块定位

### 1.1 一句话定位
本模块负责将零散的、处于启用状态的知识结果（结构化知识对象与知识切片）组装并固化为特定版本的“知识包”，作为最终交付给 Agent 消费的统一知识载体，并提供版本化管理能力。

### 1.2 模块价值
为知识交付提供明确的边界与版本控制，确保业务在不同时期使用的知识集合可追溯、可回滚。通过“同一时间仅一个版本启用”的机制，保障知识检索结果的一致性与稳定性。

### 1.3 本模块负责
- 知识包的创建与版本生成
- 知识包版本的启用与停用控制
- 知识包版本组成内容的查看与更新（生成新版本）
- 知识包版本的列表管理与状态维护

### 1.4 本需求不做
- 知识结果的生产与标准化处理（由 M-PRD-6、M-PRD-7、M-PRD-8 负责）
- 知识包对外的具体 API 检索协议（属二期增强或外部对接范畴）
- 知识包的自动质量评估（属二期质检与治理范畴）

### 1.5 上下游边界
- 上游输入：已启用的结构化知识对象（问答对、术语等）、已启用的非结构化知识切片。
- 下游输出：处于启用状态的特定版本知识包。
- 与其他模块的关系：
  - M-PRD-7 结构化知识构建：提供结构化知识对象作为知识包版本的组成部分。
  - M-PRD-8 非结构化切片构建：提供知识切片作为知识包版本的组成部分。
  - M-PRD-11 构建结果验证：读取当前启用的知识包版本进行搜索测试。

## 3. 使用场景

### 3.1 场景一：首次发布知识包
- 场景描述：项目初期知识构建完成，知识运营人员需要将首批知识打包发布，供 Agent 使用。
- 触发角色：知识运营人员
- 前置条件：项目内已有处于启用状态的结构化知识或知识切片。
- 预期结果：成功创建知识包的初始版本（如 V1.0），并将其状态切换为“启用”，Agent 可基于此版本提供服务。

### 3.2 场景二：知识更新与版本迭代
- 场景描述：业务知识发生变更，新增了部分问答对并废弃了旧知识，需要更新知识库。
- 触发角色：知识运营人员
- 前置条件：当前已有一个启用的知识包版本。
- 预期结果：基于当前启用版本或重新选择内容创建新版本（如 V2.0），确认无误后启用新版本，旧版本自动停用，实现平滑升级。

### 3.3 异常/边界场景：启用包含已失效内容的版本
- 场景描述：知识运营人员尝试启用一个历史版本，但该版本中引用的部分知识结果已被上游模块停用或删除。
- 触发角色：知识运营人员
- 前置条件：目标版本的组成中存在上游状态异常的引用。
- 预期结果：系统提示该版本包含失效内容，允许用户确认后继续启用（失效内容在检索时自动过滤），或建议用户基于该版本剔除失效内容后生成新版本。

## 4. 核心对象

> 仅写业务对象，不写数据库表、英文字段名、SQL、接口路径。

| 对象 | 是否新对象 | 对象说明 | 关键属性（中文） | 关联状态/关系 |
|------|------------|----------|-----------------|---------------|
| 知识包版本 | 是 | 知识结果的特定集合快照，代表某一次打包的知识全貌 | 版本名称、版本号、创建时间、最后更新时间 | 状态：启用 / 停用 |
| 知识包组成关系 | 是 | 记录特定知识包版本与具体知识结果（对象/切片）之间的引用关联 | 引用类型、引用对象 ID | 关联知识包版本与知识结果 |

### 4.1 对象约束补充
- 知识包版本的唯一性规则：同一项目知识空间内，同一时间只能有一个知识包版本处于“启用”状态。
- 知识包组成关系的归属关系：组成关系强依赖于知识包版本，记录的是引用而非物理拷贝；多个版本之间知识形态保持一致（均可包含结构化知识与切片）。
- 知识包版本的可用条件：必须至少包含一条有效（未被删除）的知识结果引用，且必须在项目方案处于“启用”状态时方可操作。

## 5. 业务事实归属与状态一致性

### 5.1 业务事实归属
- 知识包版本启用/停用状态的唯一事实来源是：本模块中的知识包版本对象状态。
- 知识结果当前可用性（是否被上游停用/删除）的唯一事实来源是：上游模块（M-PRD-7、M-PRD-8）中对应知识结果的状态，本模块仅做引用检查。

### 5.2 状态一致性要求
- 本文档涉及的对象状态必须与《概念模型》一致。
- 任何状态切换必须严格遵循“同一项目内仅一版本启用”的互斥原则。

## 7. 详细功能需求

### 7.1 功能点一：创建知识包版本

#### 功能描述
将当前项目内处于启用状态的零散知识结果打包，生成一个新的知识包版本快照。多个版本之间支持的知识形态一致。

#### 触发角色
- 知识运营人员

#### 前置条件
- 项目知识空间处于“启用”状态。
- 项目方案处于“启用”状态。
- 项目内至少存在一条“启用”状态的知识结果。

#### 输入
- 版本名称（必填）
- 选择的知识结果集合（至少一条）

#### 正常流程
1. 知识运营人员点击“创建新版本”。
2. 系统展示当前项目内所有处于“启用”状态的可选知识结果，按知识形态（问答对、术语、切片）分类展示。
3. 知识运营人员勾选需要打包的知识结果，并输入版本名称。
4. 系统校验输入合法性并保存。
5. 系统生成新的知识包版本对象，状态默认为“停用”，并建立对应的知识包组成关系。

#### 异常/拦截
- 当未输入版本名称时，系统应拦截并提示“版本名称不可为空”。
- 当未选择任何知识结果时，系统应拦截并提示“请至少选择一条知识结果”。
- 当项目内无可用的知识结果时，系统应拦截创建操作并提示“当前项目内无可用的知识结果，请先完成知识构建”。

#### 输出结果
- 新的知识包版本对象。
- 知识包版本与所选知识结果的组成关系。

#### 状态变化
- 新建的知识包版本：初始状态为“停用”。

#### 业务规则
- 新创建的版本不会自动启用，必须由用户手动执行启用操作。
- 多个版本之间知识形态一致，均可自由组合结构化知识对象与知识切片。

#### 与其他模块的边界/影响
- 本功能不负责知识结果内容的实际拷贝，仅建立引用关联。

---

### 7.2 功能点二：启用知识包版本

#### 功能描述
将指定的知识包版本设为当前项目的生效知识集。由于同一时间只能有一个版本启用，此操作会自动停用原有的启用版本。

#### 触发角色
- 知识运营人员

#### 前置条件
- 目标版本存在且当前处于“停用”状态。

#### 输入
- 目标知识包版本 ID

#### 正常流程
1. 知识运营人员在列表页点击目标版本的“启用”操作。
2. 系统检查目标版本中是否包含被上游停用或删除的知识结果。
3. 系统检查当前项目内是否已有处于“启用”状态的版本。
4. 若存在已有启用版本，系统提示用户确认替换。
5. 用户确认后，系统将原有版本状态更新为“停用”，将目标版本状态更新为“启用”。

#### 异常/拦截
- 当目标版本中无任何“启用”状态的知识结果时，系统应拦截并提示“该版本中无可用知识内容，无法启用”。
- 当目标版本中包含被上游停用的内容时，系统应提示“该版本包含已停用的知识内容，启用后这些内容将不可被检索，是否继续”。

#### 输出结果
- 目标版本状态更新。
- 原启用版本（如有）状态更新。

#### 状态变化
- 目标知识包版本：由“停用”变为“启用”。
- 原启用知识包版本：由“启用”变为“停用”。

#### 业务规则
- 严格保证同一项目知识空间内同一时间最多只有一个版本处于“启用”状态。
- 启用操作属于高风险操作，必须有明确的二次确认提示。

#### 与其他模块的边界/影响
- 本功能对下游的输出是：全局唯一的生效知识集合，供 M-PRD-11 和 C-PRD-2 读取。

---

### 7.3 功能点三：更新版本组成（生成新版本）

#### 功能描述
为保证版本的不可变性与可追溯性，对已有知识包版本组成的更新操作，将以“另存为新版本”的方式进行，原版本保持不变。

#### 触发角色
- 知识运营人员

#### 前置条件
- 目标版本存在。

#### 输入
- 新版本名称
- 增删后的知识结果集合

#### 正常流程
1. 知识运营人员在某版本详情页点击“更新组成”。
2. 系统带入该版本原有的知识结果勾选状态，并展示项目内其他可选内容。
3. 知识运营人员调整勾选状态，输入新版本名称。
4. 确认提交后，系统基于新的勾选集合创建一个全新的知识包版本，状态为“停用”。

#### 异常/拦截
- 当更新后的集合为空时，系统应拦截并提示“版本至少需保留一条知识结果，无法将组成清空”。

#### 输出结果
- 全新的知识包版本对象及其组成关系。

#### 状态变化
- 原知识包版本：保持不变。
- 新知识包版本：状态为“停用”。

#### 业务规则
- 对知识包组成的任何修改都不应直接覆盖原版本，以保证历史版本随时可查、可回滚。

#### 与其他模块的边界/影响
- 无特殊影响。

## 8. 自然语言伪代码

### 8.1 主流程：创建知识包版本

```text
当 知识运营人员 执行 创建新版本 时，系统执行：
1. 校验 当前项目知识空间是否处于"启用"状态；
2. 若 不是，则返回 提示"当前项目知识空间已停用，无法创建知识包版本"；
3. 校验 当前项目方案是否处于"启用"状态；
4. 若 不是，则返回 提示"当前项目方案已停用，无法创建知识包版本"；
5. 校验 填写的版本名称是否为空；
6. 若 为空，则返回 提示"版本名称不可为空"；
7. 校验 勾选的知识结果集合是否为空；
8. 若 为空，则返回 提示"请至少选择一条知识结果"；
9. 创建 知识包版本对象，记录版本名称与创建时间；
10. 更新 知识包版本状态为"停用"；
11. 创建 知识包组成关系，关联该版本与所选知识结果；
12. 返回 创建成功结果。
```

### 8.2 状态切换流程：启用知识包版本

```text
当 知识运营人员 执行 启用版本 时，系统执行：
1. 校验 目标版本当前是否处于"停用"状态；
2. 若 不是，则返回 提示"该版本已处于启用状态"；
3. 校验 目标版本中是否存在至少一条上游状态为"启用"的知识结果；
4. 若 不存在，则返回 提示"该版本中无可用知识内容，无法启用"；
5. 判断 目标版本中是否包含上游状态为"停用"的知识结果；
6. 若 包含，则提示"该版本包含已停用的知识内容，启用后不可被检索，是否继续"；
7. 校验 当前项目内是否已存在处于"启用"状态的其他版本；
8. 若 存在，则提示"当前项目已有启用版本【XXX】，启用此版本后，原有版本将自动停用，是否继续"；
9. 若 知识运营人员确认继续，则将 原启用版本 更新为"停用"状态；
10. 将 目标版本 更新为"启用"状态；
11. 返回 启用成功结果。
```

## 9. 关键业务规则

| 规则编号 | 规则内容 | 优先级 |
|----------|----------|--------|
| R-M-PRD-10-01 | 同一项目知识空间内，同一时间最多且仅有一个知识包版本处于“启用”状态。 | 高 |
| R-M-PRD-10-02 | 知识包管理采用版本快照机制，对已有版本内容的修改必须生成新版本，保障历史可追溯。 | 高 |
| R-M-PRD-10-03 | 多个版本之间的知识形态保持一致，均可包含结构化知识对象与非结构化知识切片。 | 高 |
| R-M-PRD-10-04 | 知识包组成关系仅记录对知识结果的引用，上游知识结果的状态变更不直接改变知识包版本的组成，但会在启用或检索时进行有效性过滤。 | 中 |

## 10. 异常与边界情况

| 场景 | 触发条件 | 处理方式 | 用户提示 |
|------|----------|----------|----------|
| 输入为空 | 创建版本时未填写名称 | 拦截操作 | "版本名称不可为空" |
| 输入非法 | 创建版本时未选择任何知识结果 | 拦截操作 | "请至少选择一条知识结果" |
| 状态不合法 | 尝试启用无任何有效内容的版本 | 拦截操作 | "该版本中无可用知识内容，无法启用" |
| 引用关系冲突 | 版本中包含被上游停用的知识结果 | 提示确认，允许继续 | "该版本包含已停用的知识内容，启用后这些内容将不可被检索，是否继续" |
| 状态冲突 | 启用版本时存在其他已启用版本 | 提示确认替换 | "当前项目已有启用版本，启用此版本后，原有版本将自动停用，是否继续" |

### 10.1 特殊边界补充
- 知识结果删除边界：若某知识结果被上游彻底删除，包含该引用的知识包版本在详情页应将该条目标注为“已删除/失效”，但不影响该版本中其他正常内容的展示与检索。
- 历史版本保留：系统不强制清理历史停用版本，允许项目内存在大量停用版本作为迭代记录。

| AC-08 | 多个版本包含对同一条知识结果的引用 | 各版本独立展示，互不影响，均能正常溯源 |

## 12. 非功能要求

| 类别 | 要求 |
|------|------|
| 一致性 | 版本状态切换后，列表页、详情页以及下游 M-PRD-11 验证模块读取的生效版本必须保持绝对一致。 |
| 可用性 | 版本创建、启用等核心操作必须提供明确的二次确认与成功/失败反馈，避免误操作。 |
| 安全性 | 仅具备权限的知识运营人员可执行版本管理操作，企业客户与系统管理员的越权访问应被严格拦截。 |
| 可追溯性 | 每次知识打包均生成独立版本，确保任何时期 Agent 使用的知识集合均可回溯审查。 |
| 扩展性 | 版本对象结构应支持后续新增“版本对比”、“一键回滚”等二期高级管理功能。 |

## 13. 依赖与约束

### 13.1 业务依赖
- 依赖 M-PRD-7 和 M-PRD-8 提供可被引用的知识结果。
- 依赖 M-PRD-4 提供知识类目结构用于版本内容的分类展示。

### 13.2 业务约束
- 同一时间项目内绝对且仅允许一个版本处于启用状态。
- 版本的更新必须采用“另存为新版本”的快照模式，不可直接篡改已固化版本的组成。

### 13.3 外部影响说明
- 本模块输出的唯一“启用版本”是 M-PRD-11 构建结果验证及 Agent 实际检索消费的唯一事实来源。
- 本模块依赖的共享规则包括：《概念模型 V4.2》中的对象定义、《角色矩阵与权限边界 V3.2》中的权限定义。
