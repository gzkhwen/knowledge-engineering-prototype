## 1. 模块定位

### 1.1 一句话定位

在 Agent 生成初始处理方案后，为知识运营人员提供手动调整入口，支持在方案确认前调整工具、工具顺序、工具输入来源和工具参数。

### 1.2 模块价值

- **对知识运营人员**：当 Agent 生成方案不完全符合当前类目需求时，可以低成本人工修正，而不是完全依赖重新生成。
- **对处理方案执行链路**：确认后的方案沉淀为稳定的流程配置，用于后续材料处理执行。
- **对 Agent 协作链路**：保留 Agent 默认生成能力，同时允许人工对生成结果进行补充和纠偏。
- **对工具来源**：工作台只消费 MCP 工具定义，不负责维护工具资产、工具协议或服务注册。

### 1.3 本模块负责

- 在运营端项目方案配置链路中提供处理方案调整入口。
- 展示 Agent 生成的默认处理方案。
- 按工具分类展示处理方案分组。
- 支持人工添加未加入当前方案的工具。
- 支持人工调整分类分组顺序和同分组内工具顺序。
- 支持人工删除已添加工具。
- 支持人工指定工具输入参数及输入来源。
- 支持在输入来源为上游工具输出时选择上游工具输出参数，并回显 Nacos 提供的真实取值路径。
- 支持保存时由系统根据来源工具节点 ID 和出参真实取值路径生成执行侧绑定表达式。
- 支持人工配置工具参数。
- 支持查看工具输出定义。
- 支持按分类分组依次确认方案，并在全部确认后保存处理方案。
- 支持输入来源异常的基础校验和提示。

### 1.4 本需求不做

- 不做工具 Hub / Nacos 控制台能力，不维护 MCP Server、协议、连接器、请求模板或工具资产。
- 不做工具版本选择；工作台添加的是 MCP 工具，不是工具版本。
- 不允许在工作台中配置工具输出字段；输出字段和出参取值路径由工具定义提供。
- 不在工作台页面暴露研发 DSL 绑定表达式；该表达式仅作为保存处理方案时的系统生成结果。
- 不做流程画布，本期仍在右侧“方案”页签以分组卡片表达流程配置。
- 不做方案执行、运行日志、结果验收和历史差异对比。
- 不做已保存正式方案的二次编辑流程；本需求只覆盖确认前的手动调整。

### 1.5 上下游边界

| 类型 | 对象 | 边界说明 |
| --- | --- | --- |
| 上游 | 项目方案配置 | 提供项目、末级类目和知识形态上下文 |

| 下游 | 材料处理执行链路 | 按确认后的工具顺序、输入来源和参数配置执行 |

## 3. 使用场景

### 3.1 场景一：查看 Agent 生成方案

- 场景描述：知识运营人员进入工作台，查看 Agent 针对当前末级类目和知识形态生成的默认处理方案。
- 前置条件：当前类目存在 Agent 生成结果或可生成方案。
- 预期结果：右侧“方案”页签按工具分类展示方案分组和工具卡片；工作台不再展示“智能方案 / 智能+人工”来源标签。

### 3.2 场景二：人工添加工具

- 场景描述：Agent 生成的方案缺少某个处理工具，运营人员需要补充。
- 前置条件：当前方案未整体保存，目标分类未确认。
- 预期结果：运营人员在添加工具弹窗中选择未添加的工具，系统将工具加入对应分类分组；已添加工具仍可查看但不可再次添加。

### 3.3 场景三：人工调整顺序

- 场景描述：工具执行顺序或分类分组顺序不符合业务预期，需要调整。
- 前置条件：目标分类分组未确认。
- 预期结果：运营人员可拖拽调整分类分组顺序；同一分类分组内工具数量大于 1 时，可拖拽调整工具顺序。

### 3.4 场景四：配置工具输入和参数

- 场景描述：工具本身正确，但输入来源或参数值需要由人工修正。
- 前置条件：目标工具所在分类分组未确认。
- 预期结果：运营人员打开工具编辑抽屉，指定输入参数、选择取值方式；选择上游工具输出时继续选择来源工具和上游工具输出参数，并查看该输出参数的真实取值路径。

### 3.5 场景五：按分类确认方案并保存

- 场景描述：运营人员逐个确认处理方案分组，最终保存完整处理方案。
- 前置条件：分类分组顺序已确定，工具参数满足基础校验。
- 预期结果：方案必须按从上到下的分类顺序确认；全部分类确认后，才允许保存为处理方案。

### 3.6 异常场景：前置输入来源失效

- 场景描述：某个工具输入来源设置为前置工具输出，但前置工具被删除，或前置工具被调整到当前工具之后。
- 前置条件：当前工具输入取值方式为上游工具输出。
- 预期结果：当前工具标记为输入配置异常，并提示“输入配置异常，请检查。”，阻止确认该分类方案。

## 4. 核心对象

| 对象 | 对象说明 | 关键属性 | 关系 |
| --- | --- | --- | --- |
| 处理方案 | 面向当前末级类目和知识形态的工具流程配置 | 项目、类目、知识形态、人工调整记录、确认状态 | 包含一个或多个分类方案 |
| 分类方案 | 按工具分类生成的方案分组 | 分类名称、工具列表、确认状态、排序 | 归属于处理方案 |
| 工具 | 处理方案中的可执行能力 | 工具名称、分类、入参、出参、参数配置 | 归属于分类方案 |
| 输入参数 | 工具接收上游工具输出或待处理文件地址信息的参数 | 参数名称、格式、取值方式、来源工具、上游工具输出参数 | 归属于工具 |
| 参数配置 | 工具执行时需要的配置项 | 参数名称、类型、默认值、必填、当前值 | 归属于工具 |
| 输出定义 | 工具执行后的出参定义 | 输出名称、格式、说明、取值路径 | 由 MCP / Nacos 工具定义提供 |
| 输入绑定表达式 | 保存处理方案时生成的执行侧输入映射 | 当前工具输入参数、来源节点 ID、出参取值路径 | 由系统生成，不在页面展示 |

### 4.1 对象约束补充

- 当前原型固定分类为：解析、分片、抽取。
- 当前示例工具包括：
  - 解析：通用解析、多模态解析、医保政策解析。
  - 分片：通用分片、自定义分隔符分片、分隔符递归分片、OCR解析专用分片、医保政策解析分片、视频声画同步分片。
  - 抽取：QA提取、摘要总结、关键词提取。
- 当前处理方案中同一个工具只能添加一次；已添加工具在添加弹窗中仍展示，但不可再次添加。
- 分类方案确认后，该分类内工具不可添加、删除、排序或编辑。
- 工具输出定义不在工作台中编辑。

## 5. 状态与一致性

### 5.1 状态定义

| 对象 | 状态 | 说明 |
| --- | --- | --- |
| 分类方案 | 未确认 | 可编辑 |
| 分类方案 | 已确认 | 当前分类方案锁定 |
| 工具 | 正常 | 输入来源和必填参数满足确认要求 |
| 工具 | 输入配置异常 | 上游来源不存在，或来源工具不在当前工具之前 |

### 5.2 事实归属

- 方案中使用哪些工具，以当前处理方案草稿为准。
- 分类方案顺序，以当前工作台右侧方案页签中的分类顺序为准。
- 工具顺序，以分类方案内工具卡片顺序为准。
- 工具入参、出参、参数类型、默认值和出参真实取值路径，以 MCP / Nacos 工具定义为准。
- 工具卡片参数回显以必填参数为主，完整参数配置在编辑抽屉中查看和修改。

## 7. 详细功能需求

### 7.1 展示 Agent 生成方案

1. 系统读取 Agent 生成的处理方案。
2. 方案内容包括：使用哪些工具、每个工具的输入、参数配置和输出定义。
3. 系统按工具分类生成分类方案。
4. 系统可在后台记录方案是否发生人工调整，但工作台页面不展示“智能方案 / 智能+人工”标签。

### 7.2 添加工具

#### 正常流程

1. 用户在“方案”页签点击添加工具。
2. 系统打开添加工具弹窗。
3. 弹窗展示 MCP 服务名称和版本号。
4. 用户选择工具分类。
5. 用户选择工具。
6. 系统展示该工具的入参和出参，不展示响应模板。
7. 用户点击确认添加。
8. 系统将工具加入对应分类方案。

#### 业务规则

- 分类区、工具列表区、参数列表区独立滚动。
- 添加弹窗中的分类固定为：解析、分片、抽取。
- 已添加工具仍展示在工具列表中。
- 选择已添加工具时，确认添加按钮置灰，按钮文案为“工具已添加”。
- 不展示工具状态。
- 不选择工具版本。
- 工具加入方案后，系统记录当前方案已发生人工调整。

### 7.3 删除工具

1. 用户点击工具卡片删除入口。
2. 系统校验当前工具所在分类方案未确认。
3. 系统删除该工具。
4. 若被删除工具是其他工具的输入来源，依赖该工具的后置工具进入“输入配置异常”状态。

### 7.4 调整顺序

#### 分类分组排序

- 分类分组数量大于 1 时，未确认分类分组支持拖拽排序。
- 已确认分类分组不可拖拽。

#### 工具排序

- 同一分类分组内工具数量大于 1 时，工具卡片前展示拖拽把手。
- 分类分组内只有 1 个工具时，不展示拖拽把手。
- 工具卡片不展示显式序号。
- 工具排序后，如果某个工具的输入来源工具被调整到该工具之后，该工具进入“输入配置异常”状态。

### 7.5 编辑工具

#### 正常流程

1. 用户点击工具卡片编辑入口。
2. 系统从右侧打开二级抽屉。
3. 抽屉包含三个模块：工具输入、工具配置、工具输出。
4. 用户配置输入参数、取值方式和参数值。
5. 用户关闭抽屉后，工具卡片回显最新输入、必填参数和输出定义。

#### 工具输入

- 模块名称为“工具输入”。
- 用户需要指定一个当前工具参数作为输入参数，用于接收前面配置的输入值。
- 只有被指定为输入参数的参数，才允许配置为来自上游工具输出。
- 第一分类分组的第一个工具取值方式固定为“待处理文件地址信息”，不可修改。
- 除第一分类分组第一个工具外，其他工具取值方式支持“上游工具输出”和“待处理文件地址信息”。
- 选择“待处理文件地址信息”时，不再展示来源工具、上游工具输出参数等后续配置。
- 选择“上游工具输出”时，需要选择来源工具和上游工具输出参数。
- 上游工具输出参数选择后，系统在选择框下方回显 Nacos 提供的真实取值路径，格式为“取值路径：{真实取值路径}”。
- 页面不展示研发 DSL 绑定表达式；保存处理方案时，系统根据来源工具节点 ID 与出参真实取值路径生成执行侧绑定表达式。
- 来源工具列表只展示当前工具之前的工具。

#### 工具配置

- 参数配置展示除输入参数外的可配置参数。
- 参数控件根据工具定义中的参数类型、默认值、必填规则渲染。
- 不展示“展示到页面”配置项。
- 修改参数只影响当前处理方案草稿，不修改 MCP 工具定义。

#### 工具输出

- 输出区域只展示工具出参名称和说明。
- 输出字段不支持在工作台编辑。

### 7.6 工具卡片展示

- 工具卡片标题区展示工具名称、展开/收起入口、编辑入口、删除入口。
- 工具卡片前不展示启用复选框。
- 工具名称后方展示展开/收起入口。
- 工具卡片展开后展示三块内容：
  - 输入：以“参数名称：取值来源”展示。
  - 参数配置：直接展示必填参数名称和当前值；无必填参数时展示“无必填参数”。
  - 输出：展示输出名称，并在输出名称后展示格式标签。
- 工具卡片不展示工具介绍、MCP 服务来源或工具状态。

### 7.7 分类方案确认

#### 正常流程

1. 用户从第一个分类方案开始确认。
2. 当前分类方案校验通过后，用户点击确认方案。
3. 系统将该分类方案标记为“已确认”。
4. 已确认分类方案不可继续编辑。
5. 用户继续确认下一个分类方案。
6. 全部分类方案确认后，保存处理方案按钮可用。

#### 业务规则

- 分类方案必须按页面顺序依次确认。
- 前一个分类方案未确认时，后一个分类方案的确认按钮不可用。
- 已确认分类方案标题后展示“已确认”标签。
- 已确认分类方案右侧展示“重新编辑”按钮。
- 只有后方相邻分类方案未确认时，当前已确认分类方案才允许重新编辑。
- 重新编辑后，该分类方案回到可编辑状态，后续保存需再次确认。

### 7.8 保存处理方案

1. 系统校验所有分类方案均已确认。
2. 系统校验不存在输入配置异常。
3. 系统校验至少存在 1 个工具。
4. 校验通过后，保存为处理方案。

## 8. 自然语言伪代码

### 8.1 添加工具

当用户点击确认添加时：

1. 如果未选择工具，则不可提交；
2. 如果工具已添加，则不可提交；
3. 如果工具所属分类方案已确认，则不可提交；
4. 创建工具节点；
5. 按工具分类插入对应分类方案；
6. 记录当前方案已发生人工调整。

### 8.2 校验输入来源

当工具输入设置为上游工具输出时：

1. 读取当前工具之前的工具列表；
2. 判断来源工具是否仍存在于前置工具列表；
3. 判断所选上游工具输出参数是否仍存在于来源工具出参定义中；
4. 若来源工具不存在、顺序不合法或输出参数不存在，则标记当前工具为输入配置异常；
5. 分类方案确认时，如果存在输入配置异常，则阻止确认。

### 8.3 生成输入绑定表达式

当保存处理方案时：

1. 遍历每个工具节点的输入配置；
2. 如果取值方式为待处理文件地址信息，则保存为文件地址输入来源；
3. 如果取值方式为上游工具输出，则读取来源工具节点 ID；
4. 读取所选上游工具输出参数对应的 Nacos 真实取值路径；
5. 按执行侧约定生成绑定表达式；
6. 将绑定表达式写入当前工具节点的输入映射；
7. 绑定表达式仅用于执行侧，不在工作台编辑页面展示。

### 8.4 分类方案确认

当用户确认分类方案时：

1. 判断该分类是否为当前第一个未确认分类；
2. 若不是，则提示按顺序确认；
3. 校验该分类内工具是否存在异常；
4. 若存在异常，则阻止确认；
5. 若校验通过，将分类方案标记为已确认。

## 9. 关键业务规则

| 编号 | 规则 | 优先级 |
| --- | --- | --- |
| R-MTP-01 | 本需求只覆盖 Agent 生成方案后的手动调整，不覆盖工具治理和方案执行。 | 高 |
| R-MTP-02 | 当前处理方案默认由 Agent 生成，人工调整发生在确认前。 | 高 |
| R-MTP-03 | 添加工具时选择的是 MCP 工具，不选择工具版本。 | 高 |
| R-MTP-04 | 已添加工具不可重复添加。 | 高 |
| R-MTP-05 | 输入来源为上游工具输出时，只允许选择当前工具之前的来源工具。 | 高 |
| R-MTP-06 | 工作台不支持编辑输出字段，输出字段和取值路径由 MCP / Nacos 工具定义提供。 | 高 |
| R-MTP-07 | 第一分类分组第一个工具的取值方式固定为待处理文件地址信息。 | 高 |
| R-MTP-08 | 分类方案必须按顺序确认，全部确认后才允许保存处理方案。 | 高 |
| R-MTP-09 | 已确认分类方案不可编辑，满足顺序限制时可重新编辑。 | 中 |
| R-MTP-10 | 删除或排序导致输入来源失效时，相关工具必须标记为输入配置异常。 | 高 |
| R-MTP-11 | 工具卡片只展示输入、必填参数配置和输出定义，不展示工具状态、工具介绍或 MCP 来源。 | 中 |
| R-MTP-12 | 输入来源为上游工具输出时，必须选择来源工具和上游工具输出参数，并回显该输出参数的真实取值路径。 | 高 |
| R-MTP-13 | 研发 DSL 绑定表达式由系统在保存时生成，工作台页面不直接展示或编辑。 | 高 |

## 10. 异常与边界情况

| 场景 | 触发点 | 处理方式 | 提示建议 |
| --- | --- | --- | --- |
| 重复添加工具 | 选择已添加工具 | 确认添加按钮置灰 | 工具已添加 |
| 分类已确认 | 尝试添加、删除、排序或编辑该分类工具 | 阻止操作 | 方案已确认 |
| 未按顺序确认 | 尝试越级确认后续分类方案 | 阻止确认 | 请按方案顺序依次确认 |
| 后续分类已确认 | 尝试重新编辑前序分类 | 阻止重新编辑 | 后续方案已确认，不能重新编辑当前方案 |
| 来源工具被删除 | 后置工具仍引用该来源 | 后置工具红色边框并提示 | 输入配置异常，请检查 |
| 来源工具被调整到当前工具之后 | 顺序调整后校验 | 当前工具红色边框并提示 | 输入配置异常，请检查 |
| 必填参数为空 | 确认分类方案或保存 | 阻止确认 | 请补全必填参数 |

## 11. 验收标准

### 11.1 正向验收

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 打开工作台方案页签 | 展示 Agent 生成的分类方案和工具卡片 |
| AC-02 | 未人工修改方案 | 方案页签不展示“智能方案 / 智能+人工”来源标签 |
| AC-03 | 添加未添加工具 | 工具加入对应分类方案，并记录方案已发生人工调整 |
| AC-04 | 已添加工具在弹窗中被选中 | 确认添加按钮置灰，并显示“工具已添加” |
| AC-05 | 编辑工具输入来源为上游工具输出 | 来源工具列表只展示当前工具之前的工具，上游工具输出参数选择后回显真实取值路径 |
| AC-06 | 查看工具卡片展开态 | 展示输入、必填参数配置和输出格式 |
| AC-07 | 按顺序确认分类方案 | 当前分类标记为已确认，后续分类可继续确认 |
| AC-08 | 全部分类确认后保存 | 保存为处理方案按钮可用并保存成功 |

### 11.2 逆向验收

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-09 | 越级确认后续分类方案 | 系统阻止确认 |
| AC-10 | 后续分类已确认后重新编辑前序分类 | 系统阻止重新编辑 |
| AC-11 | 删除被引用的来源工具 | 引用该工具的后置工具展示输入配置异常 |
| AC-12 | 将来源工具调整到当前工具之后 | 当前工具展示输入配置异常 |
| AC-13 | 输入配置异常时确认分类方案 | 系统阻止确认 |
| AC-14 | 在工具编辑抽屉中寻找输出字段配置 | 页面不提供输出字段配置入口 |

## 12. 非功能要求

| 类型 | 要求 |
| --- | --- |
| 一致性 | 工具分类、工具名称、参数类型、默认值、必填规则、输出格式和出参取值路径必须与 MCP / Nacos 工具定义保持一致 |
| 可用性 | 添加、删除、排序、编辑、确认、重新编辑和保存操作必须有明确可用 / 禁用状态 |
| 可追溯 | 保存处理方案时应保留工具顺序、输入来源和参数配置 |
| 可维护性 | 工作台不重复维护工具定义，避免与工具来源产生双写 |

## 13. 依赖与约束

### 13.1 业务依赖

- 依赖项目方案配置提供入口、项目、末级类目和知识形态上下文。
- 依赖 Agent 提供初始处理方案。
- 依赖 MCP / Nacos 工具定义提供分类、工具、入参、出参、出参取值路径和参数配置。
- 依赖处理方案管理保存最终确认方案。

### 13.2 业务约束

- 手动调整只发生在方案确认前。
- 已确认分类方案默认不可编辑，需要满足顺序规则后才能重新编辑。
- 已保存处理方案不在本需求中展开二次编辑。

## 14. 待确认项

- 历史版本页签是否需要支持方案差异对比。
- Agent 重新生成覆盖人工修改前是否需要增加确认提示。
